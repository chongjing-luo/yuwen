# 教学设计（第二阶段 / S3）

服务机制节点：**全部20节点的S3设计落点**。三阶段唯一操作方法是`work/methodology/lesson-preparation/语文备课操作规程.md`；专项规则引用`work/methodology/manuals/S3-教学设计手册.md`的`MM-S3-01`—`MM-S3-23`。上位原则与终审判据分别在`work/methodology/lesson-preparation/备课基本原则.md`和`work/methodology/lesson-preparation/逐页功能审计与放行协议.md`，本skill只编排输入、门禁与输出，不另造教学设计方法。

创建v2.6课程数据与设计锁时读取 `../_shared/lesson-lineage-contracts.md` 的G2节。

## 硬输入

- 当前 `教案.md`、`_meta/G1_owner_approval.json`、`_meta/lesson_plan_lock.json`
- G0证据档案（用于核对，不重新夺取教案裁决权）
- 原则注册库 `work/principles/registry.yaml`（设计时逐页引用原则 ID）
- 手法库（困难→手法映射）、视觉规范

## 受控类别的使用方式

课堂事件类型、活动、教师动作、学生动作、参与结构、产物、感官通道、反馈方式、页面内容对象、语义关系、显示约束、排版操作和知识生命周期的当前定义，只从`work/methodology/lesson-preparation/教学设计类别注册表.json`读取；skill不复制可能漂移的类别表。

先选择**课堂实际发生的事件类型**，再由事件类型决定最低合同。准确讲授、情境叙述、朗读停留和过渡沉静不为字段齐全虚构任务；它们可以没有即时产物和修订，但必须有后续检验。只有学生主要通过自主加工获得增量时才登记主活动；讲授、提问、示范登记为教师动作，讨论、分组、展示分别登记为学生动作、参与结构或产物。辅助活动只在确有次要学习机制时使用。

既往课例与用户举例都是候选材料，不是固定答案。先把举例改写为“它可能想解决的问题、期待的学生变化、现实约束”，再用本篇原文、获批目标/KID、学情和证据需求校验这份意图本身；意图不准可修正，覆盖不全须主动补充。只在原形式仍是最佳选择时照用；否则可修改、拆并、替换或不采纳，并在选法理由中记录依据。不为举例、类别数量或表面多样设配额。若真实课例显示类别重叠或遗漏，按注册表规则优先合并、改名或删除，经边界审查后再扩展。

具体版式不从封闭模板家族中挑选。S3先确定一个连贯语义场景或组织意图，再冻结内容对象、语义关系、必须共视/分时、主次层级、连续锚点、密度上下限、边界与揭示时序；随后建立教材优先的视觉来源档案，并为每个信息状态冻结准确可见内容、构图关系、阅读路径、空间比例、配图裁决和剧本片段。S4只依据真实文字长度完成精确几何、资产、美学和多媒体实现。若S4需要改变语义分组、分页、上屏内容或配图功能，退回S3。

## 步骤

1. **验证G1**：先运行 `python3 scripts/validate_lesson_plan.py <lesson_plan_lock.json>`。失败立即停止；不得自造回执或边写设计边补教案。
2. **建立课堂运行逻辑**：把教案每个阶段拆成课堂事件，先写事件类型，再写学生所见所闻、实际思考路径、可能而不强迫发生的情绪变化、动作、理解增量、教师完整作用、后续检验、过渡、时间和失败信号；任务、等待、回应、产物、反馈与修订分别只在该事件类型的`requires`要求时写入。学生体验决定事件顺序、讲授完整度、活动强度、沉静与交流时机。输出唯一人读审批稿`教学设计.md`，显式标出lesson ID、事件ID与页面ID，采用“按课时连续的课堂正文＋设计索引”：正文呈现真实课堂，索引紧凑登记事件—页面/状态、知识、类别、信息状态、后续检验和删除损失；另设全课视觉来源说明，并让每个物理画面的配图资格、来源或派生方式、教学功能、时机、位置权重与事实伦理边界可直接审阅。其余完整机器合同留在`lesson.json`，不得用治理字段淹没课堂。
3. **先写评估标准再写页面**（P-37）：每个事件/页面预先规定学生接收或动作、后续检验/第一次后用、删除损失与失败信号；再按`event_type.requires`分别规定真实等待、可能回应与诚实分支、可见或可听产物、反馈及必要修订，不把一套生成合同强加给所有事件。把G1证据拆为数量、互异性、规定主体、独立/闭卷条件、必含成分、覆盖阶段、载体、字数计算对象与后用原子；逐项绑定真实事件和同一主体的证据，不用多人拼接、教师讲过或模糊累计冒充达成。
4. **建立v2.6课程数据**：新候选的`lesson.json`使用`schema_version: "2.6"`，必须含 `lesson_plan_binding`、`lesson_plan_scope`、`text_contract`、`objectives`、`three_questions`、`kp_scope`、`visual_source_profile` 与 `pages[]`；其中`three_questions`只投影G1按需设置的贯穿问题，允许空列表。范围投影绑定合同哈希、总时长与收束方式；每页绑定获批`stage_id`，PG04—PG09再绑定获批`objective_ids/lesson_kids`，PG01—PG03保持两项空列表。全课完整覆盖目标与必教/检索旧知KID。`canonical_lines`须逐条存在于绑定的UTF-8文本源，G1 `KID→KP`与G2投影严格一致；顶层字段闭合，不得另造课堂效果字段。存量v2.2—v2.5按冻结标准仍可strict验证，不追溯改写。
5. **完成每页条件合同与物理画面蓝图**：在`activity_contract.event_type`登记主导课堂事件，再按注册表要求填写共同页面合同和条件字段：所有事件保留困难、功能、接收/动作、后续检验、删除损失；`artifact/wait/feedback/revision/normal_counterexample`逐项只在该事件的`requires`命中时强制。再填四组S3责任对象：①`knowledge_payload[]`登记KID及知识生命周期；②`activity_contract`登记事件类型，必要时登记主/辅助学习机制，并登记教师动作、学生动作、参与结构、产物、感官通道、反馈方式及非模板理由；③`student_experience`写学生感知、思考、可能情绪、实际行动和理解变化；④`slide_design`先从注册表登记唯一主要`presentation_role`及非模板理由，再登记语义单位、内容对象、语义关系、共视/分时、主次层级、连续锚点、密度判断、边界理由、前台元素与逐态集合，并为每态建立`physical_screen`。角色由学生第一注意对象、当页主动作和删除损失共同裁决；无法确定时重划语义边界。PG01—PG03只定位课题、路径或阶段，内容对象用CO09，`objective_ids/lesson_kids/knowledge_payload`保持空列表；不得为过机器门禁伪挂知识。PG05支撑页必须写`support_link`，说明从何页/何句或`lesson_entry`触发、返回哪一后续页及回来后怎样重读原文；无消费者的资料页删除。标题先直接命名对象或职责，文学性放到副标题、引文和画面。同时从本课/单元教材中核验可用配图、人物、色调和图形语言，形成全课视觉来源档案；逐屏写准确可见元素、构图关系、阅读路径、空间比例、配图资格/来源或派生方式/教学功能/出现时机/位置与视觉权重/事实伦理边界和剧本片段。多个KID可以同页，但须属于同一意义单位、具有可见关系、主要加工动作一致并确有共视需要；固定条数、字数或“一页一个KID”只作预警，不作硬门。人读稿把审核需要的课堂与版式裁决压缩进设计索引，但全课视觉来源与上述逐屏配图信息必须完整、可直接审阅，不得只藏在`lesson.json`。
6. **写逐页真实剧本**：S3用`script_segments`按真实顺序写`transition/instruction/narration/reading/task/wait/calibration/feedback/summary/cut`。讲授、叙述、朗读和总结写完整可说语言，不切成虚假提问；每次真实发布任务后都紧接属于该任务的`wait`，可能回应、分支、反馈与修订按`event_type.requires`分别落实。片段绑定`information_states`和触发时点，时间盒按顺序完整覆盖全部真实片段，不设固定数量。需要学生先答、先回应或先提交作品的事件，答案性元素与反馈不得早于相应的`after_student_response`、作品提交或同伴回应触发；剧本点名的现场作品、关系图、断点、检查项或回取栏必须对象化并进入对应状态。逐字稿须可无声试讲，不得以“提问—讨论—总结”代替真实语言。
7. 逐字段执行反样板检查；审查是否把讲授、朗读和沉静伪装成学生任务，也审查各事件是否缺其`requires`规定的等待、首答保护、回应分支、产物、反馈或修订。连续事件若类别名称不同但认知动作、参与结构、产物、反馈和教师作用高度同构，仍须返工；连续讲授也须有内容依赖和注意节奏。逐课时审计教师输入与学生输出密度、材料切换和恢复段，不能让数页各自可执行却合成持续过载；来源辨界卡不得自报类别；G1批准的证据规格不得在S3降格。
8. **生成审批候选并停止**：先检查按课时课堂正文可连续无声试讲、设计索引可回查关键裁决且两层无重复方案，再运行 `validate_lesson_schema.py --lesson-json <lesson.json> --strict` 与反样板检查；通过后提交当前`教学设计.md`、`lesson.json`与G1锁的路径和SHA-256，请用户审批。此时状态只能是“S3教学设计审批候选·待用户审批”，不得生成`design_lock.json`或进入S4。用户举例、此前“继续/执行”或对旧版本的批准不得推定为批准当前哈希。
9. **真实批准后锁定G2**：只有用户明确批准当前Markdown—课程数据—G1锁组合后，才写`_meta/G2_owner_approval.json`，回执精确绑定三项哈希；再写含非空S3内容作者`author_id`及`owner_approval`绑定的`_meta/design_lock.json`，运行 `validate_lesson_lineage.py design <design_lock.json>`。本地验证只证明结构与血缘一致，不认证人类身份。

## 放行条件（进入 S4 的门槛）

- G1锁、所有者回执和当前教案哈希一致；
- schema 校验通过（`scripts/validate_lesson_schema.py`，通用 schema 落地后）；
- 每页知识分页、事件类型与条件合同、九类页面呈现角色、支撑页触发—返回、学生体验五项、语义单位、共视/分时、主次层级、动态密度、元素级信息状态、视觉来源、逐物理画面蓝图、台词状态绑定和完整逐页剧本全部通过v2.6机器门和人读审查；
- 反样板检查 0 发现（或逐条给出保留理由）；
- 机制节点覆盖自查：K1（KP 全落点）、U1（首答保护）、U7（反例路径）、J5（节奏）逐项确认；
- 人读教学设计与lesson.json同源，design lock有效；
- 用户已明确审批当前`教学设计.md`，G2所有者回执与Markdown、lesson.json、G1锁三项哈希一致；
- 桌面声明：本设计未经课堂检验（P-12）。

## 上游锁定与回退

不得改变目标、必教/检索旧知KID、defer、贯穿问题、阶段顺序、完整母版总时长或宏观收束。可优化事件粒度、活动手法、页面数量、分组方式、过渡和阶段内时间。发现G1逻辑不可执行时，退回 `yuwen-author-lesson-plan`，重新审核并使旧设计失效。

`教学设计.md`、`lesson.json`或G1锁任一改变，旧G2审批回执和design lock立即失效；必须重建审批候选并由用户重新审核，不能只替换哈希。

## 常见错误

- 先做视觉美化再确定教学版式功能；把“美观、简洁、大气”当版式理由；字段用默认串充数；
- 活动多但无后用消费者（U8/G5）；教师抢答（U1）；在G2暗改教案合同。
