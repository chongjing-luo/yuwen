# 教学设计（S3）

服务机制节点：**全部 20 节点的主战场**——每页 18 字段合同即机制节点的设计追溯落点。上位规则：`work/备课基本原则.md`（P-01…P-44）；协议：`work/备课/逐页功能审计与放行协议.md`（A-01 十六项合同）。

## 输入

- S2 证据档案（KP 清单、困难、三问、解释边界）
- 原则注册库 `work/principles/registry.yaml`（设计时逐页引用原则 ID）
- 手法库（困难→手法映射）、视觉规范

## 步骤

1. **先写教案**（所有者裁决 2026-08-16 / MM-S3-13）：人读教案先行——教学目标分素养维度目标＋现实迁移目标；享受写为全课过程品质声明（不单列目标）；知识清单逐项绑定知识卡或注明无卡缺口。**教案经所有者审核讨论通过后**才进入以下步骤。
2. **先写评估标准再写页面**（P-37）：每页预先规定学生动作、可见产物、第一次后用、删除损失、失败信号。
3. 建课程数据（lesson schema）：`text_contract`（绑定源包哈希）/ `knowledge_refs` / `three_questions` / `pages[]`。
4. 每页填全 18 字段合同（A-01）：前页输入、当前困难、唯一功能、第一眼合同、信息状态、学生动作、可见产物、真实等待、有界反馈、可见修订、后页调用、正常反例、视觉职责、第一人称接收、删除损失、连续理解增量 + 程序注意力预算 + 故事回接句。
5. **逐字段问"这是本页的具体情况还是通用话术"**——模板默认串会被 `scripts/checks/check_trace_evidence.py` 检出，等于未落实（反样板纪律）。
6. 参与结构按五要素设计（J1/U7）：个人生成 → 小组共作 → 公开表达 → 听众任务 → 可见修订；正常反例每类有诚实路径（P-17）。
7. 首答态跨渠道保护（U1，P-34/42）：屏幕、台词、学习单、版式四渠道逐一核对泄答。
8. 教师角色设计（U3，P-23/32）：精讲内容、示范点、后置归纳引用学生原话的方式。
9. 全课节奏五维自检（J5，P-33）：认知动作×感官通道×社会结构×作品形态×情绪，连续三页三维修相同即返工。
10. 时间盒设计：单页一个主要认知对象（U5，P-22/35），timeboxes 秒数和 == 页分钟×60。
11. 运行：`node tests/test_<lesson>.js`（若建）+ `python3 scripts/checks/run_principle_checks.py --lesson-js <lesson.js> --name <id>`。

## 放行条件（进入 S4 的门槛）

- 教案已经所有者审核讨论通过（回执在案，MM-S3-13）；
- schema 校验通过（`scripts/validate_lesson_schema.py`，通用 schema 落地后）；
- 反样板检查 0 发现（或逐条给出保留理由）；
- 机制节点覆盖自查：K1（KP 全落点）、U1（首答保护）、U7（反例路径）、J5（节奏）逐项确认；
- 桌面声明：本设计未经课堂检验（P-12）。

## 常见错误

- 先画版式再找功能（A-01 明令禁止）；字段用默认串充数（45/46 页的历史教训）；
- 活动多但无后用消费者（U8/G5 孤儿产物）；教师抢答（U1）。
