# 重大方案决策压测

本 skill 是三阶段备课主链之外的工程治理支持工具。它只读压测重大候选，在冻结前查清事实、暴露关键取舍并取得确认；不编写教案、教学设计、PPT、锁或审查回执，也不替代 `yuwen-audit-lesson`、`yuwen-flow` 或 `yuwen-selfcheck`。

执行依据：`AGENTS.md`的范围控制与净结果交付规则、`docs/architecture/项目设计方案.md`第6节的操作准入规则，以及涉及冻结候选时的`work/evaluation/convergence.md`。

## 进入条件与分流

先检查排除项，命中任一项就分流，不再检查进入条件：

- 真实意图尚不清楚：转入 `interview-me`，一次澄清一个根本问题；不得同时运行两套访谈，也不采用其可选的 `docs/intent/` 持久化输出。
- 意图已经清楚但尚无候选方案：交给相应责任阶段或创作流程先形成候选，本skill不代替方案生成。
- 任务只是执行、改字、搬移、格式整理等清晰操作：直接执行，不启动压测。
- 请求实质是G0—G4产物质量审查：交给对应阶段skill或 `yuwen-audit-lesson`，本skill不判P0/P1/P2。
- 对象已经按冻结标准进入审查：不得以本次新发现追溯否决；新决定只进入后续版本。只有用户明确开启后续版本，才交给责任阶段重新形成候选。

排除项均未命中，并同时满足下列条件，才开始压测：

1. 用户显式调用 `$yuwen-grill-decisions`；
2. 用户想实现的结果、适用对象、成功标准和范围已经确认；
3. 已有可陈述的候选方案或明确的候选决定；
4. 当前对象尚未冻结，或者用户已明确为下一版本重新开启决策。

## 数据流合同

**读取**：经确认的意图与范围、候选方案、适用的项目权威文件、候选当前状态与冻结信息。涉及教学方案时，再读取其有效上游锁和已经声明的目标、KID、K/U/J作用或手册依据，不自行扩展教学目标。

**写出**：只在聊天中给出当前决策结论，包括范围、已定决定、未决决定、约束、风险和正确的下游责任阶段。压测期间不写项目文件，不创建根目录术语表、第二套决策目录或任何替代性正式路径。

**放行条件**：关键事实已经核验；所有会实质改变用户可见结果、规则、信息结构、成本、风险或证据效力的分支已经处理；未决项及其依赖没有被代理推荐掩盖；用户明确确认当前结论或明确授权代理裁决指定决定。

**质量证据**：问题能够回指候选中的真实分支或权威文件；事实、代理建议、用户决定三者可区分；停止时可以说明哪些分支已闭合、哪些仍未闭合。桌面压测不构成课堂效果、门禁通过、所有者哈希批准、独立审查或宿主放行证据。

若分支会改变教学目标、知识范围、学习机制或学生体验，结论必须列出该候选已有的受影响K/U/J节点和作用方向；没有真实映射时不收束，退回责任阶段补足。本skill不新增节点，也不据桌面讨论声称教学作用已经发生。

## 压测步骤

### 1. 定义压测对象

用一段简短陈述固定：本次压测的对象、已经确认的目标、包含范围、不包含范围、当前候选和当前版本状态。若这些内容仍需猜测，停止并回到意图澄清。

### 2. 建立决策树

根节点是候选方案；只纳入会实质影响结果的决定。为每个决定标记：

- 它依赖哪些事实或先决决定；
- 可行选项及不可逆成本；
- 失败时会损害什么；
- 它会影响哪个下游阶段或对象；
- 最终由用户决定，还是已被用户明确委托给代理裁决。

可由现有规则唯一推出的小问题直接按规则处理，不扩大成用户决策。实现细节尚未到其责任阶段时，不提前进入当前前沿。

### 3. 代理查事实

文件是否存在、锁是否有效、代码或数据怎样运行、既有规则写了什么，均由代理使用只读检查核验，不把可查事实反问用户。核验结果在提问前简要给出来源；无法核验的内容标为假设或风险，不把用户断言冒充文件、哈希或外部事件证据。

### 4. 只问当前前沿

当前前沿只包含先决事实和先决决定均已解决的问题。每轮提出1—3个相互独立的当前问题；依赖本轮答案的问题留到下一轮。每题包括：

- 问题及其影响；
- 必要时给出互斥选项；
- 代理的推荐答案及理由。

用户回答后更新决策树，不重复已定问题。用户明确把某项决定委托给代理时，代理可以在已确认范围内作出清晰裁决；教学决定仍须由责任阶段写入候选并接受其目标映射和门禁，涉及扩大范围、外部写入、费用、安全风险、正式审批或放行的决定不能由一般性委托替代专项授权。

### 5. 做反向压力测试

对每个重大决定至少检查与其风险相称的反面：最强替代方案、失败条件、撤销成本、边界案例和下游连锁影响。只检查会改变决定的反面，不为了显得彻底而制造低价值问题。

三阶段对象必须遵守依赖前沿：没有有效G1时，不决定S3分页、活动和剧本；没有有效G2时，不决定S4视觉实现；压测不得用下游偏好反向修改上游合同。

### 6. 收束并等待确认

当前前沿为空时，给出一份简短的当前决策结论：

- 对象与范围；
- 已确认或已授权裁决的决定；
- 仍存在的风险或外部依赖；
- 正确的后续责任阶段；
- 请求用户明确确认。

明确确认前不执行方案，不生成正式文件、回执或锁。确认只结束本次压测，不自动授权实施；实施仍须用户另行明确要求并交给正确的责任阶段。确认也不等于对未展示文件及其哈希的G1/G2批准，更不等于G4独立审查或宿主放行。

若用户要求中止，立即停止，分别列出已定项、未决项及被未决项阻塞的下游问题；不得把中止表述为已经收敛，也不得用代理推荐填满空缺。

## 禁止越界

- 不把“穷尽”理解为无限提问；重大分支闭合或用户中止即停止。
- 不边讨论边改教案、教学设计、课程数据、PPT、方法论、原则注册库、schema或正式决策文档。
- 不创建或补写G1/G2回执、G0—G4锁、双审记录及任何 `released` 状态。
- 不以新问题、新原则或新检查器追溯否决已经冻结的在审候选。
- 不把本skill与 `interview-me`、内容作者skill或独立审查skill同时混用成一个无边界流程。
