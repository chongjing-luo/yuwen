# 课后反思与知识沉淀（S9）

服务机制节点：**全部节点的迭代闭环 + J7（警惕"这节课很顺"作为质量证据）**。模板：`work/teaching/_shared/reflection/课后反思模板.md`。

## 输入

- S6 观察数据与学生作品
- S8 掌握热图与错因
- 本课课程数据与审查记录

## 步骤

1. 按模板填写：先证据后判断——每个结论必须有观察记录/作品/数据支撑；"很顺/很好"不是证据（J7 流畅错觉）。
2. 三目标两本账逐项核对：课堂证据落在哪，缺的信号如实写"未采集"。
3. 逐节点归因（只归因有证据的节点）：现象 → 设计侧原因（指向具体页面/字段）→ 修订提案。
4. U7 专项：沉默/想不起/不同意的学生实际走了什么路径？
5. **原则修订提案**：触发证据 → 拟新增/修改原则 → 服务节点 → 进入 STANDARD 下一版本（不追溯否决本轮，收敛规则）。
6. `.learnings` 回流：重大发现按 LRN 条目记入 `.learnings/LEARNINGS.md`；Recurrence ≥ 2 的提案 promote 为原则条目（注册库同步）。
7. 产出下一轮迭代决定：课程数据修改清单 / 回教 KP / 新增观察信号 / 明确不做的事与理由。

## 放行条件

- 每条归因引用了具体证据；
- 原则修订提案全部映射机制节点且登记进入版本；
- 下一轮决定可执行（落到字段/页面/KP 级）。

## 常见错误

- 反思写成感想（无证据无归因）；
- 发现的问题不落字段——下一轮同样的问题无法被机器拦截；
- 把一次课的个案直接升格为原则（应先入 learnings，复发才 promote）。
