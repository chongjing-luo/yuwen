## 一、目标、边界与完成定义

### 1.1 项目目标

从教材、单元任务、教师用书、课程标准和高考真题中，建立一套能够：

1. 回答“教什么、为什么教、如何迁移”的高中语文知识体系；
2. 同时呈现人文维度与语言维度；
3. 将每个知识点映射到高考评价体系，但不夸大“教材直接命题”；
4. 从原子知识点向上汇总为单元、册级和全局地图；
5. 让所有重要结论都能在两分钟内回到已核实的规范来源载体复核。

### 1.2 本阶段不做什么

- 不直接生成完整教案、课堂活动方案或 PPT。
- 不把网络题库、AI 输出或 MinerU OCR 当作最终权威来源。
- 不为前言、后记、单元任务和教师用书分别生成知识点卡。
- 不在模板和受控词表冻结前启动全量批写。
- 不把“可能考”“主题相近”写成“高考直接衔接”。

### 1.3 完成定义（Definition of Done）

项目只有同时满足以下条件才算完成：

- 81 张知识点卡、28 份单元图谱、5 份册级总表全部达到各自评分门槛；
- 教材先行阶段的 81 张知识卡、28 份单元图谱和 5 份册级总表通过验收，并生成 G-TB 锁定记录；
- G-TB 之后，17 年高考配对卷的清洗、题组切分、题型汇编和真题 EKP 研究通过单独的高考规格验收；
- 教材核心产物、真题产物、映射表和全局地图均有稳定 ID、依赖记录、版本和评审记录；
- 所有硬性否决项为 0，引用、ID 和跨文件关系为 0 断链；
- 所有直接引文已经回看规范来源载体，核心结论证据覆盖率为 100%；
- 上游变更已经触发并完成所有受影响下游成果的复核。

## 三、知识体系与数据契约

### 3.1 双维度仍是组织主轴

```text
人文维度：单元主题 → 文本母题 → 文化议题 → 育人指向
语言维度：任务群 → 文体知识 → 语言现象 → 读写方法 → 迁移任务
```

母题不是“标准答案”。它属于研究解释，必须满足：

- 基于文本，而非脱离文本贴价值标签；
- 面向学生能够理解和讨论的真实问题；
- 至少有两处相互独立的文本证据；
- 明确标注为“有依据的解释”，不得冒充教材明示结论。

### 3.2 原子知识点

知识卡不是散文式概述。卡内每个可复用知识结论都拆为原子知识点，至少包括：

| 字段 | 要求 |
|---|---|
| `kp_id` | 全库唯一且稳定 |
| `statement` | 一句话表述一个可教、可学、可迁移的结论 |
| `dimension` | 人文或语言为主维度，可加次标签 |
| `knowledge_type` | 事实、概念、程序、策略、解释或价值辨析 |
| `primary_layer` | 必备知识、关键能力、学科素养、核心价值之一 |
| `mapping_reason` | 解释为什么归入该主层级 |
| `evidence_ids` | 至少一条有效证据；核心解释至少两条文本证据 |
| `confidence` | 已核实、有依据的解释、暂定、冲突或未核实 |

四层主归属按知识点自身的操作定义判断，不再使用“能归更高层就一律取最高层”的规则。一个事实知识不会因为具有育人意义就被改标为核心价值；跨层影响通过关系表表达。

### 3.3 稳定 ID

册码固定如下：

| 册码 | 册次 |
|---|---|
| `B1` | 必修上册 |
| `B2` | 必修下册 |
| `X1` | 选择性必修上册 |
| `X2` | 选择性必修中册 |
| `X3` | 选择性必修下册 |
| `TB2` | 必修下册教师教学用书，仅用于来源 ID |

推荐格式：

```text
知识卡：CARD-B1-U01-01
知识点：KP-CARD-B1-U01-01-001
证据：EV-CARD-B1-U01-01-001
单元图谱：UNIT-B1-U01
册级总表：BOOK-B1
真题：EXAM-2025-NC2-Q014
```

活动、整本书阅读、语言专题和诵读卡使用独立类型码，但仍遵守“一份有效学生教材切分包对应一张复合卡”。中文标题可改，稳定 ID 不随标题或切分序号变化。选择性必修下册两个以 `13_` 开头的源文件必须由清单分配不同永久 ID。

### 3.4 状态机

```text
planned → drafted → linted → primary_reviewed ─────────────→ accepted → published
             ↑                    │       └→ secondary_reviewed ─┘
             └──── rework ←───────┤                    │
                                  └→ adjudication ─────┘

accepted / published --上游变化→ review_required → linted
```

- `accepted` 之前不得进入下游汇总。
- 同一成果必须先达到 `linted`，再进入内容评审；需要第二复审时，主审通过也不能直接验收。
- 任一评审要求返工时进入 `rework`，修改后从 `drafted` 重新运行检查。
- 评审结论冲突时进入 `adjudication`；仲裁结果只能转入 `accepted` 或 `rework`。
- 上游内容变化后，下游进入 `review_required`，更新后重新运行检查与受影响维度评审。
- `published` 仅表示已进入阶段性交付，不表示以后不可修订。

## 四、来源治理与证据协议

### 4.1 来源等级与载体状态

“书或文件所代表的来源”与“本地实际文件载体”必须分开建模：一个 `source_id` 可以对应原始 PDF、切分 PDF、MinerU `_origin.pdf`、JSON、网页快照等多个 `artifact_id`。来源等级描述来源权威性；载体真实性描述当前文件能否承担终审。

| 等级 | 来源 | 可承担的证明责任 |
|---|---|---|
| `S1` | 正式教材、配套教师用书、课程标准、考试院文件、正式试卷及官方答案 | 教材事实、课程定位、命题事实 |
| `S2` | 国家级辞书、权威版本、学术专著、同行评审论文 | 文学史、作者背景、术语和研究解释 |
| `S3` | 正规教育媒体、教研机构解析 | 辅助解释和交叉核对 |
| `S4` | 聚合题库、个人网页、AI 输出 | 仅用于发现线索，不得单独支撑正式结论 |

载体另标为：`正式电子版`、`纸本扫描件`、`切分衍生`、`OCR衍生`、`网页快照`、`图像`、`计算结果`。本地扫描件只有在版本、来源链和真实性完成核验后，才可作为该 S1 来源的规范载体；不能因为内容看似教材就自动称为“S1原件”。

每个来源必须指定唯一 `canonical_artifact_id` 作为终审载体，并为每个 artifact 独立记录哈希、取得方式、`derived_from`、转换过程和 `authenticity_status`。真实性状态受控为 `unverified / verified / conflict / rejected`；只有 `verified` artifact 可被指定为 canonical。现有 `full.md`、JSON 和 MinerU `_origin.pdf` 均默认为衍生载体，只帮助定位；不得自动成为终审规范载体。

### 4.2 来源登记表

来源登记与文件登记分别记录：

```text
Source：source_id、题名、编著者/发布机构、出版社或发布渠道、版次、
ISBN/文号、发布日期、适用范围、source_level、版权备注、canonical_artifact_id

Artifact：artifact_id、source_id、carrier_type、本地路径、原始URL、获取日期、
页数/大小、SHA-256、derived_from、转换过程、authenticity_status、是否canonical

SourceRelation：relation_id、relation_type、source_id_from、source_id_to、
relation_status、evidence_ids、verifier、verified_at
```

教师用书—学生教材配套关系使用 `relation_type=edition_match`，`relation_status` 受控为 `verified / incompatible / unknown`。不得把该状态只写在知识卡自由文本中。

执行前应建立以下参考原件库：

```text
Data/reference/
├── curriculum/       # 课程标准、高考评价体系及正式说明
├── junior/           # 初中关联所需的正式教材、目录或可核验版本信息
├── policy/           # 四川用卷等考试院正式公告
└── gaokao/           # 2023—2026试卷、答案、评分资料及来源元数据
```

第三方题库可以作为检索入口，但不得替代正式试卷；非官方答案必须明确标注权威等级。

### 4.3 最小证据记录

每条证据至少包含：

```text
evidence_id
claim_id + target_id + field_path
claim_type
source_id + artifact_id + source_level + carrier_type
locator_type + locator
exact_quote（引文型证据必填）
support_relation = supports / context / contradicts
verification_status + verifier + verified_at
```

`locator` 按载体分支：

- PDF：规范 artifact、物理页码（1 起）、印刷页码（可 N/A）、必要时 bbox；
- HTML：网页快照 artifact、快照时间、标题层级/锚点和文本片段；
- 图像：artifact、页/帧和 bbox；
- 派生计算：输入 claim/evidence/artifact ID、公式或算法、口径、工具及版本、输出结果。

PDF 引文必须目视核对 `canonical_artifact_id` 指向的规范主文件页面；读取 PDF 文本层、MinerU `_origin.pdf` 或 OCR 文本都不算终审核对。`full.md` 行号会随重新解析变化，不得作为唯一定位符。

基础阶段必须建立 `split_manifest`。其中 `split_page` 与 `original_page_start` 都按 1 起计数，映射公式固定为：

```text
original_page = original_page_start + split_page - 1
```

每条映射记录规范主文件 artifact ID、切分 artifact ID、起止页、双方页数、页数恒等检查和 `mapping_verification_status`。144 个切分包全部执行首页/末页边界或渲染指纹核验；不得用抽样结果支撑 100% 定位有效率。

### 4.4 主张类型

| 类型 | 含义 | 最低证据要求 |
|---|---|---|
| `Q` | 教材或原文直接引语 | 在 S1 的规范 artifact 上逐字目视核对 |
| `F` | 作者、册次、体裁、年代等事实 | S1；教材未载时补 S2 |
| `I` | 母题、意象作用、文化意义等研究解释 | 至少两处文本依据并写推理 |
| `M` | 四层、任务群、纵向贯通等框架映射 | 框架映射须有官方定义+本课证据；纵向关系须有两端证据+递进理由 |
| `R` | 教学建议 | 教师用书证据，或明确标为“本项目建议” |
| `E` | 高考衔接判断 | 已登记真题小问和具体 KP；潜在题型不得冒充实证 |
| `D` | 字数、频次、跨年统计等派生结论 | 输入 ID、口径、公式/算法、工具版本和可复算结果 |

所有进入正式成果的非空需证字段必须有证据编号或明确的 `N/A + 原因`。所有 `I` 类解释均须至少两处相互独立的文本依据。来源等级高不等于延伸解释自动成立。

### 4.5 教师用书覆盖不足的处理

原“教学提示”拆为：

1. 教材学习提示；
2. 配套教师用书意见；
3. 本项目教学建议。

`TB2` 只有在版次、ISBN、出版信息和适用教材完成配套核验后，才能作为必修下册的配套教师用书证据。若 `edition_match` 关系的 `relation_status=unknown`，只能表述“该教师用书提出”，不得上升为当前学生教材的确定编者意图。其他四册统一写“未取得同册教师用书，待补证”。不得留空猜测、套用必修下册意见或把学生教材学习提示冒充教师用书意见。

教师用书指标分开报告：

- 来源可得率 = 有确认配套教师用书的知识卡数 ÷ 81；
- 实际引用率 = 引用有效教师用书证据的卡数 ÷ 有确认配套且存在相关条目的卡数。

客观缺源不扣单卡内容分，但分子、分母和配套状态必须公开。

### 4.6 高考衔接等级

| 等级 | 定义 | 表述边界 |
|---|---|---|
| `M1 直接调用` | 真题明确出现篇名、原句、注释，或可唯一识别的教材任务 | 可称“直接衔接” |
| `M2 方法迁移` | 陌生材料回链到具体已验收 KP，并要求相同能力动作 | 称“迁移衔接”；泛称“都考阅读能力”不成立 |
| `M3 一般关联` | 仅主题、文体或潜在题型相近 | 只能称“教学相关” |
| `M0 无可靠关联` | 当前没有足够证据 | 不强行建立映射 |

真题 ID 必须细化到小问，例如 `EXAM-2025-NC2-Q014-A`。试卷、答案和评分资料按 `document_role=paper / answer / scoring` 分别建立 Source，各自具有独立的发布机构、来源等级和 canonical artifact，再用 SourceRelation 建立对应关系。非官方答案不得继承正式试卷的 S1 等级，也不得支撑“官方答案”或“官方评分标准”结论。

任何具体年份、卷别、题号、分值和答案都必须回链到已登记 artifact 和小问 ID。题数以原卷为准，不预设固定题量或跨年总题数。

### 5.2 特殊内容包

- 活动单元：按活动步骤建立 `subtask_id`，提取完成活动所需的语文能力、活动证据和社会文化议题。
- 整本书阅读：按导读、推进、研讨、分享等教材实际阶段建立 `subtask_id`；不得凭空补齐教材未设阶段。
- 语言专题：按知识专题建立子项，必须包含正例、反例或应用任务。
- 古诗词诵读：每册一张复合卡，篇目使用 `subtext_id`；简化教学建议，但不降低引文与事实核验标准。

### 5.3 单元知识图谱

单元图谱只能汇总本单元所有 `accepted` 卡和对应单元任务，必须包含：

- 卡片和 KP 覆盖清单；
- 人文维度与语言维度矩阵；
- 共性、差异、前提、深化、比较、迁移等关系；
- 单元学习/研习任务原文定位及能力拆解；
- 高考衔接等级与真题回链；
- 前后单元递进；
- 冲突、缺源和待核实项。

单元图谱不能只是复制知识卡摘要，也不能新增无法回链到卡片或单元任务的确定性结论。

### 5.4 册级总表

册级总表汇总该册全部已验收单元图谱、古诗词诵读卡和前言信息，负责：

- 统一术语、合并同义知识点、保留不同语境下的差异；
- 描述跨单元的前置、深化和迁移关系；
- 给出人文主线、语言主线和任务群分布；
- 标明本册教师用书证据覆盖情况；
- 输出可检索的知识点索引和未解决问题清单。

### 5.5 真题解构与映射表

每道题及其小问建立稳定 ID，记录卷别、题号、规范 artifact 定位、题干、分值、答案来源等级、四层/四翼/情境编码、能力动作和原子考点。真题基础解构不写 KP 链接或 M 等级。

真题基础解构不得与教材知识卡生产并行。必须先通过教材锁定门：81 张知识卡、28 份单元图谱和 5 份册级总表全部 `accepted`，课程标准和教材来源链通过最终检查；之后才能启动真题清洗、题组切分和题型汇编。正式“真题—KP”映射仍作为独立关系表，必须等待真题 ID、EKP ID 和教材知识点 ID 均稳定。

### 5.6 全局知识地图

全局地图以 5 份册级总表和考点映射总表为唯一上游，至少包含：

- 人文维度树；
- 语言维度树；
- 任务群、文体、方法和素养的交叉关系；
- 初中关联、必修到选必的纵向递进；
- 高考 M1/M2 映射；
- 冲突、空白和低证据覆盖区域。

## 六、评估标准

### 6.1 硬性否决项

出现任一项即不计分、退回返工，并冻结受影响的下游成果：

1. 伪造、错引、张冠李戴，或作者、篇名、册次、年代、题号、分值等关键事实错误；
2. 直接引文无法定位，事实性主张无适配来源，或任一 `I` 类研究解释不足两处文本证据；
3. 合编课文中有文本未覆盖，整个必填模块缺失，或特殊内容包使用错误模板；
4. 把研究解释写成教材明示，把学习提示冒充教师用书意见，把网络解析或 OCR 冒充原始证据；
5. 原子知识点没有主层级、映射理由或有效证据；
6. 将任何非 M1 记录写成高考“直接衔接”，或引用未登记真题作为实证；
7. 使用未验收上游生成单元、册级或全局成果；
8. 数量、ID、版本或跨文件链接不一致，导致来源链无法回溯。
9. 使用非现行课标、自由改写任务群名称，或把学习任务群误作固定课型/固定教学法；
10. 机械铺满四项核心素养却无语言实践依据，或把学业质量水平直接当作课文、知识点、题目难度标签。

分数不能抵消否决项。

### 6.3 统一评分计算规则

6.10 已固定各维度的分值锚点。Task F2 只负责把每个锚点展开为可回答“通过/不通过”的观察项，不得擅自改变锚点分值；覆盖型观察项同时记录合格数与应检数。同一锚点展开为多个观察项时默认等权。

```text
维度得分 = 维度权重 ×（通过检查点权重之和 / 适用检查点权重之和）
```

- `N/A` 仅在 Schema 明确允许且写明理由时剔除分母；不得用 `N/A` 掩盖缺失。
- 每个维度按四舍五入保留 0.5 分，总分为各维度得分之和，不再二次取整。
- 评分表必须列出检查点、证据、通过与否、分子/分母和扣分原因；禁止只凭整体印象给分。
- 单审成果以主审对最终版本的得分为最终分。
- 未触发仲裁的双审成果要求两位评审分别达到总分和全部单项门槛；最终分为两人对同一最终版本评分的算术平均值。
- 任一评审判为不通过、总分差超过 5 分、单维度差超过 2 分或否决判断不一致，均进入仲裁，不得用平均分直接通过。
- 仲裁者由协调者指定，必须独立于生产者和前两位评审。仲裁者先形成有约束力的问题裁决；成果按裁决修订并重新 lint 后，由仲裁者对最终版本完整重评分。仲裁分即最终分，且仍须达到总分、单项和否决门槛；原两份评分保留为审计记录。
- 校准包采用更严格的例外：仲裁只用于解决口径和修改问题，不能用仲裁分替代双评。修订并重新 lint 后，原两位评审必须对同一最终版本重新评分，二者各自均不低于 92、均判通过，且分差回到允许范围；否则 G2 不通过。

各模板的二元检查点和扣分锚点属于冻结契约的一部分；改变检查点等同于 Schema 变更，必须重新版本化并评估对既有分数的影响。

### 6.11 评审与抽检

1. 生产者对所有成果进行 100% 自检；结构、ID、必填字段、占位符、引用路径和断链执行 100% 自动检查。
2. 独立主审对 81 张卡和所有上层成果进行 100% 内容评审；主审不能是生产者。
3. 第二复审的必检集合包括：10 张校准卡、5 份校准图谱、每册首个生产单元、全部特殊内容卡、整本书阅读卡，以及主审最终得分距门槛不超过 5 分的“贴线成果”。重叠项只计一次。
4. 从剔除必检集合后的其余知识卡集合 `R` 中抽样。必检卡可以满足“每单元至少一张”；先找出仍未覆盖的单元集合 `U`，抽样总额固定为 `Q = max(ceil(|R| × 25%), |U|)`。所有字符串先做 Unicode NFC 规范化，再以 UTF-8 编码；`canonical_json` 遵循 RFC 8785。种子取 `SHA-256(canonical_json([schema_version,batch_id,review_round]))`，候选排序键取 `(SHA-256(canonical_json([seed,card_id])), card_id)`。先在每个未覆盖单元内取排序最前一张，再将剩余额度按“册码 × material_type”候选数用最大余数法分配；余数并列时按 `canonical_json([book_code,material_type])` 升序裁决，层内哈希并列时按 `card_id` 升序裁决。种子、分层配额、候选清单和结果一并保存。
5. 28 份单元图谱、5 份册表、全量真题研究产物、考点映射总表和全局地图均执行 100% 第二复审。
6. “同一批次”指 `deliverables.jsonl` 中同一批次 ID 下的成果；“重大缺陷”指 P0 或 P1；重大缺陷率按“含 P0/P1 的第二复审成果数 ÷ 本次第二复审成果数”计算。
7. 抽到 P0 时，将该成果所在单元扩大为 100% 第二复审；无单元归属的诵读卡则扩大其批次。重大缺陷率超过 10% 时，将该 `batch_id` 全批扩大为 100% 第二复审。
8. 双审评分、通过和仲裁规则统一遵守 6.3；保存评分表、问题单、修改记录、抽样种子和最终裁决，使复审可重现。

### 6.12 缺陷等级与返工

| 等级 | 定义 | 处理 |
|---|---|---|
| `P0` | 否决项、来源造假、严重事实错误、依赖断裂 | 冻结下游；本项返工；所有派生成果失效重审 |
| `P1` | 不触发 6.1 否决项，但足以导致总分或单项低于门槛的重大质量缺陷 | 整项返工，复查相关维度与链接 |
| `P2` | 措辞、格式或非核心遗漏 | 修正后复核，冻结版本前清零 |

- 定义 `总分缺口 = max(0, 总分门槛 - 实得总分)`，`最大单项缺口 = max(0, 各单项最低分 - 对应实得分)`。无 P0，且总分缺口不超过 5、最大单项缺口不超过 2 时可以定向返修；任一条件超出即整份重做。
- 同一批次第二次未通过，扩大到 100% 复审；第三次未通过，更换执行者并重新校准样板。
- 任何成果进入 `accepted` 前，开放的 P0、P1、P2 必须全部清零；未核实线索移入问题清单，不作为开放缺陷留在正式成果中。
- 通过后记录版本和内容哈希；上游改变时按依赖关系触发差异复核。

## 八、并行边界与协作规则

### 8.1 可并行

- G2 最终冻结后的不同单元；
- 单元简报完成后的不同知识卡；
- G-TB 通过后，真题阶段内部不同文档的版面/小问清点和结构化解构；
- 各册全部单元通过后的五份册级总表；
- 不同成果之间的自动检查与内容评审。

同一成果内部不得并行跳步，必须先完成自动检查并进入 `linted`，再进行内容评审。

### 8.2 必须串行

- 来源字段 → Schema 和引证规范；
- 候选 Schema、词表、量表版本化 → 校准 → 修订并最终冻结 → 批量生产；
- 全部教材卡、单元图谱和册级总表 `accepted` → G-TB 教材锁定 → 真题 G0/G1；
- 单元简报 → 单元卡；
- 单元全部卡通过 → 单元图谱；
- 全册单元和诵读通过 → 册级总表；
- 真题与 KP 双方 ID 稳定 → 正式映射；
- 全部上游通过 → 全局地图。

### 8.3 共享状态管理

- `sources.jsonl`、`artifacts.jsonl`、`source_relations.jsonl`、`deliverables.jsonl`、`taxonomy.yaml` 和主 ID 清单只由一个协调者合并；
- 执行者按单元提交独立文件，禁止多人同时修改同一知识卡或图谱；
- 跨册争议进入统一问题单，由协调者裁决后更新受控词表；
- 每次批量执行前后都运行一致性校验并保存报告。

## 九、主要风险与控制

| 风险 | 影响 | 控制措施 |
|---|---|---|
| OCR 粘连、漏字、注释移位 | 引文和语言分析失真 | OCR 只定位；所有引文回看规范 artifact；高风险项双审 |
| 教师用书只覆盖必修下册 | 教学提示口径不一 | 三类教学字段分开；缺源显式 N/A；单独统计覆盖率 |
| 母题和文化标签主观化 | 把价值判断冒充教材结论 | 标记主张类型；两处文本依据；独立评审 |
| 任务群等术语数量不一致 | 全库分类漂移 | 以课标原文建立受控词表，禁止自由造词 |
| 现有样板错误被批量继承 | 规模化返工 | 样板降级；10卡5图校准；达到92分后冻结模板 |
| 真题来源或卷别不可靠 | 高考映射失真 | 原件、政策、答案分开登记；题数按原卷生成 |
| 多执行者并发导致 ID 冲突 | 关系断链 | 单一协调者维护主清单；一文件一所有者；自动校验 |
| 上游修订未传导 | 汇总内容过期 | 记录依赖和哈希；变化触发下游 `review_required` |
| 为追求覆盖强行建立关系 | 知识地图虚假繁密 | 允许 M0 和“未核实”；不以关系数量作为绩效 |

## 十、批准后立即执行的准备任务

按以下顺序启动，不越过门禁：

1. 先只处理教材侧：完成课程标准、教材和教师用书的 Source/Artifact/Relation 登记与页码映射；高考试卷清单保持冻结，不启动试卷处理；
2. 形成教材侧受控词表、ID 规则、V2 模板、评分检查点和状态机；
3. 按已确定的 Schema 实例化教材卡、单元图谱和册级总表，并建立自动校验器；
4. 返修必修上 U1，并完成 10 卡、5 图代表性校准包；
5. 根据校准结果修订并最终冻结教材契约，重新校验校准产物，使其全部转为 `accepted`；
6. 用户检查校准结果后，进入剩余 23 个单元垂直生产包；
7. 五册教材、28 份图谱和 5 份册表全部 accepted 后，生成 G-TB 锁定记录，才将任务交给试卷 Agent。

在 G-TB 教材锁定门通过前，试卷正式生产进度固定记为 `blocked_by_textbook`；当前教材正式生产进度仍记为：知识卡 `0/81 accepted`、单元图谱 `0/28 accepted`、册级总表 `0/5 accepted`。
