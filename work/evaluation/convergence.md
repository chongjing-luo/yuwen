# 收敛规则

## 一、要解决的问题（历史教训）

2026-08-10 至 08-14，《氓》课件在 4 天内迭代 V4→V6.6 共 9 个大版本、约 13 个候选。V6.5 V4 双审 P0=P1=P2=0、获得"可进入受控试教"资格后，旋即被 V6.6 复审判 NOT_RELEASED。根因不是审查太松，而是：

1. **标准无版本锚定**：每轮新发现被立即用于否决在审候选，审查标准持续前移；
2. **桌面审查失去外部锚点**：真实试教从未发生，"更严的桌面审查"成为唯一可做的改进，形成无限回归；
3. **原则事后追认式增长**：43 条原则几乎全部产生于失败复盘，没有准入门槛，存在无限增长倾向。

## 二、标准版本锚定制

1. 标准以 **STANDARD-X.Y** 命名，实体 = 原则注册库的一个冻结状态（registry.yaml 哈希）+ 生效的检查器集合。
2. **候选进入审查时冻结标准版本**：审查开始即在审查回执记录 STANDARD 版本与注册库哈希；审查期间注册库的任何变更不影响本轮评审。
3. **不追溯否决**：新原则、新检查器进入 STANDARD-下一版本，只约束此后的新候选；不得用于推翻按旧版本进入流程的候选。
4. 当前版本：**STANDARD-1.0**（2026-08-14，112 原则 / 20 节点全覆盖 / 检查器见注册库 enforcement）。

## 三、放行判定（桌面账的停止规则）

按冻结标准完成审计的候选，依下列规则判定，防止无限打磨：

| 状态 | 条件 | 结论 |
|---|---|---|
| 返工 | 存在 P0/P1/P2 | 修复后由原审查者复验 |
| 模块重建 | 模块 >1/4 物理画面被判 P0-P2，或同根因贯穿 ≥3 页（P-43） | 停止局部润色，重划分页面 |
| **桌面已验·待试教** | 连续两轮仅余 P3（且 P3 均登记观察方法） | 放行进入 S6 试教 |
| 阻塞 | 依赖缺失（如官方答案源、真实班级） | 如实登记 blocked 与解除条件 |

- "一轮审查零发现"不构成放行证据——先怀疑审查力度（P-29）；
- 放行结论必须携带声明：**桌面验证只证明设计条件，效果待真实课堂**（P-12）；
- 试教后出现的问题走 S9 反思归因，产生的原则进入 STANDARD-下一版本。

## 四、新原则准入（防无限增长）

新增原则条目必须同时满足：

1. **北极星映射**：服务至少一个机制节点（K/U/J），写明因果依据；
2. **触发事件**：记录产生该原则的真实失败/证据（哪一页、哪次审查、哪个数据），不接受"原则上更好"的预防性立法；
3. **强制方式**：声明 machine_check / design_trace / review_gate 之一，或 role=meta + 理由；
4. **收敛检查**：与既有原则语义重叠的合并而非新增（注册库校验器做节点覆盖核对）。

同类约束适用于机制节点与 skill：无节点归属的内容不收录（准入规则，见三目标机制文档 §1.2）。

## 五、外部锚点

桌面审查的收敛终点是**真实课堂**。连续两轮桌面 P3-only 即应放行试教，而不是发明更严的桌面标准——课堂证据（S6 观察表、mastery ledger）才是三目标的最终裁判。在真实试教发生前：

- 全部产物状态只能写"桌面已验·待试教"；
- 课堂账为空且明确标注（`scripts/checks/run_principle_checks.py` 的 classroom_account 字段）；
- 不以桌面指标（页数、字段完整度、审查轮数）冒充教学效果。
