# 课后反思模板（按机制节点归因）

> 使用方法：一次试教/授课后填写。每条观察必须先给证据（观察表记录、学生作品、作业数据），
> 再归因到机制节点（K/U/J），最后给出可执行的修订提案。没有证据的印象不进入本表——
> 包括"这节课很顺"（J7：顺畅可能是流畅错觉，不是学习增益）。

## 一、基本信息

| 项 | 内容 |
|---|---|
| 课次 / 日期 | |
| 课程数据版本 | （lesson.js 路径 + 提交哈希） |
| 标准版本 | （审查时冻结的 STANDARD-X.Y） |
| 观察表 | （路径） |
| 作业/测评数据 | （mastery ledger 路径与条数） |

## 二、三目标两本账（先记事实，再下判断）

| 目标 | 课堂证据（观察表/作品/数据） | 判断 | 归因节点 |
|---|---|---|---|
| 学到更多（K1-K5） | 例：单元卷 KP 掌握率、作业闭卷题得分 | | |
| 真正学懂（U1-U8） | 例：个人末答抽样、修订痕迹率、迁移题质量 | | |
| 享受学习（J1-J7） | 例：主动开口率、自发回读、课后谈论 | | |

未采集到的信号如实写"未采集"，不得以桌面推演代替。

## 三、逐节点归因（只填有证据的节点）

```
### 节点 <K/U/J 编号>（节点名）
- 证据：<观察记录/学生作品/数据，注明来源与数量>
- 现象：<发生了什么/未发生什么>
- 归因：<设计侧原因，指向具体页面/环节/字段>
- 修订提案：<可执行的改动；涉及课程数据字段的写明字段>
```

## 四、异常与反例（U7 专项）

- 沉默/想不起/不同意的学生走了什么路径？该路径真实可完成吗？
- 有学生被迫伪造观点的时刻吗？
