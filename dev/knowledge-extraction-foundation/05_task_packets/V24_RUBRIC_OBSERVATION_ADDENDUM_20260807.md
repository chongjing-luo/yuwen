# V2.4 评分观察项与研究验证协议（候选附录）

> 用途：供协调者合入 V2.4 执行与评估控制稿，解决“同一张卡为什么能评出 19.5/14.5，以及换一位评审能否复算”的问题。
>
> 状态：candidate。用户/协调者批准前，不改变 `2.0-textbook` 的六类量表权重、单项门槛、总分门槛、R01—R10 或既有 `accepted` 状态。
>
> 适用顺序：先执行证据硬门，再执行本附录的质量评分，最后执行双审/批次/研究有效性判断。高分不能抵消前置硬门失败。

## 1. 需要冻结的三层评价

| 层 | 回答的问题 | 判定用途 |
|---|---|---|
| A. 合格性硬门 | 这个版本是否有资格被评分？ | Schema、SHA、来源、Claim—Evidence、Q 引文、I 双证据、ID/链接、上游和 R/P 缺陷；任一失败即 `rework/blocked` |
| B. 产物质量分 | 在合格版本中，内容质量达到什么水平？ | 使用 `2.0-textbook` 冻结权重和单项门槛；必须由观察项复算 |
| C. 方法与过程有效性 | 这套提取方法能否稳定扩批？ | 双审一致性、缺陷逃逸、留出集表现、教学查询可用性和批次稳定性 |

三层不能混算。A 层失败时可以保留诊断性分数帮助返工，但不得给出正式 `pass`；C 层失败不一定否定一件已合格产物，却会暂停扩批并触发方法校准。

## 2. 观察项记录契约

每份评审必须绑定同一组冻结输入：

```yaml
deliverable_id: CARD-B2-U06-03
artifact_version: 0.2.0
artifact_sha256: ...
contract_version: 2.0-textbook
rubric_sha256: ...
rubric_interpretation_version: 2.0-textbook-observation-1
claim_register_sha256: ...
upstream_snapshot_sha256: ...
validator_run_id: ...
```

每个评分观察项至少保存：

```yaml
observation_id: OBS-<deliverable>-<dimension>-<checkpoint>-NNN
dimension_id: evidence
checkpoint_id: quote_fidelity
scope_query: <稳定 ID/field_path 集合，不使用 Markdown 行号>
applicable_count: 19
pass_count: 19
result: pass|fail|N/A
na_kind: null
na_reason: null
evidence_refs: [...]
defect_ids: []
reviewer: ...
reviewed_at: ...
```

覆盖型检查点允许在评分表中聚合显示 `pass_count/applicable_count`，但必须保留失败 ID 清单；判断型检查点必须拆成可回答“是/否”的子观察项，不能直接凭印象写 4.5/5。

## 3. 唯一计分方法

```text
单观察项得分     = observation_weight × result(pass=1, fail=0)
覆盖型检查点得分 = checkpoint_weight × pass_count / applicable_count
判断型检查点得分 = checkpoint_weight × 通过子观察项权重 / 适用子观察项权重
维度得分         = round_half_up_to_0.5(该维度检查点得分之和)
总分             = 各维度得分之和，不再二次取整
```

- 子观察项默认等权；非等权必须预先写入机器可读 observation manifest，评审后不得改权重。
- `N/A` 只允许使用证据协议冻结的 `not_applicable / permitted_unavailable / future_locked / no_reliable_relation`，并由两审一致确认；缺失必需内容不得记 N/A。
- 某检查点适用分母为 0 时，报告 `N/A + reason`，不得写成 100%。
- 评审中发现正文漏列 Claim，只能扩充分母并重新核算；不得删除 Claim 或观察项缩小分母。
- 任一内容修改改变 artifact SHA，旧观察项、旧分数和旧双审结论立即失效，新版本从 DG1 重走。

## 7. 真正独立的双审

1. 生产者、主审、第二复审三角色分离。
2. 主审和第二复审在各自记录封存前，不读取、转述或协商另一人的分数、缺陷和结论。
3. 两审必须绑定同一 artifact SHA、claim register SHA、rubric SHA、observation manifest 版本和上游 snapshot。
4. 每位评审分别达到总分和所有单项门槛，且 R01—R10=0、最终 P0/P1/P2=0。
5. 两审决定一致、总分差≤5、单维度差≤2；任一超限、硬否决不一致、N/A 分母不一致或 Claim 分母不一致均进入独立仲裁。
6. 讨论只能发生在两份原始评审封存之后。内容修订产生新 SHA 后，两位原评审须对新版本完整重审；旧分数不滚存。

批次另报告：

```text
观察项一致率 = 两审相同判断的适用观察项数 / 两审共同适用观察项总数
P0逃逸率 = 二审首次发现而主审原始记录未发现P0的成果数 / 二审成果数
P1逃逸率 = 二审首次发现而主审原始记录未发现P1的成果数 / 二审成果数
P2逃逸率 = 二审首次发现而主审原始记录未发现P2的成果数 / 二审成果数
```

- 单件 pass 仍要求两审结论一致；批次观察项一致率目标 ≥90%。
- 任一 P0 逃逸：立即暂停该生产者/同源链扩批并审计受影响下游。
- P1 逃逸率 >10%：批次转黄，停止提高 WIP，完成根因复盘和全批复核。
- P2 逃逸率 >20%：不否定已修复单件，但下一批前重新校准边界/措辞样例。
- 修订后的 P0/P1/P2=0 不能覆盖首次检出的逃逸记录。

## 8. 研究有效性评价（与逐件验收分开）

逐件双审证明“当前成品合格”，但不能单独证明提取方法具有召回率和可迁移性。V2.4 应增设一个不改产物状态的研究验证层：

### 8.1 封存留出集

- 在扩展到下一大册前，从尚未生产的教材卡中按“册码 × material_type”分层、用公开 SHA 种子选出 12 张留出卡；高风险稀有类型不足时强制纳入。
- 另选 4 个单元图谱和首份册表作为上层汇总留出件。
- 两名标注者在不看生产者输出的条件下，先分别建立 Gold Claim/KP/任务义务/证据清单，再由第三人仲裁封存。
- 生产者只获得源材料和冻结契约，不获得 Gold；结果锁 SHA 后才揭盲匹配。

### 8.2 指标与通过值

| 指标 | 计算 | 通过值 |
|---|---|---:|
| 关键事实/任务义务召回率 | 命中的 Gold 关键事实或强制任务 / Gold 总数 | 100% |
| KP 语义精确率 | 与 Gold 匹配且边界正确的输出 KP / 输出 KP | ≥90% |
| KP 语义召回率 | 被输出覆盖的 Gold KP / Gold KP | ≥90% |
| KP F1 | 精确率与召回率调和平均 | ≥90% |
| 主维度/知识类型/四层标签 macro-F1 | 在语义匹配 KP 上计算 | ≥85% |
| Claim—Evidence 支持准确率 | 完整支持对应 Claim 的绑定 / 绑定总数 | 100% |
| Q quote span 与 locator 准确率 | 规范 PDF 逐字命中且可定位 / 全部 span | 100% |
| 关系边精确率 | 双方证据与关系语义均成立的边 / 输出边 | ≥90% |
| 未支持正式主张率 | 无合格证据的 asserted Claim / asserted Claim | 0% |

语义匹配由不知道产物来源的仲裁者按“一一匹配/一对多合并/边界过宽/漏项”规则裁决，并同时报告分子、分母和 95% bootstrap 区间；不能只报一个总分。

### 8.3 教学查询试验

以固定查询集检验项目目标“教什么、为什么教、如何迁移”：

- 12 个查询覆盖单课事实、文本解释、语言方法、单元任务、跨课比较、册级递进和证据回查；
- 每个回答只能消费 accepted 上游，并列出 KP/EV/Artifact；
- 查询任务完成率 ≥90%，核心事实与证据准确率 100%；
- 每条核心结论均能在 2 分钟内回到规范载体复核；
- 至少两位语文教师或等价专家以 5 分量表评价可用性，中位数 ≥4，且无“可能导致教学事实错误”的严重意见。

留出集任一 R01/R02/R03 级错误、关键事实/任务召回率不足 100%、证据硬指标不足 100% 或 KP F1<90%，均暂停扩批，回到模板/提示/样板校准；不得以逐件最终修订后的高分宣称方法已经验证。
