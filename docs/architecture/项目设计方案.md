# 项目设计方案（v0.9 · 待审计）

## 1. 目标与北极星

**三目标**：让学生①学到更多有价值的知识、②真正学懂、③享受学习。

实现方式：三目标拆解为 **20 个机制节点**（K1-K5 知识 / U1-U8 学懂 / J1-J7 享受，定义见 `work/evaluation/三目标实现机制.md`），每个节点四层对齐：因果依据 → 环节落点 → 强制点 → 度量（桌面/课堂两本账）。

**准入法庭**：任何新内容（数据条目、方法论条目、手册规则、校验器、skill 步骤、产物字段）入库必须声明服务的机制节点，否则不收录。节点同时是课堂证据的归因坐标系。

**诚实边界（两本账）**：桌面账证明"设计条件具备"，课堂账（唯一来源：真实试教/作业/测评数据）证明"效果发生"。两者永不混写；未试教前一切产物状态只能是"桌面已验·待试教"。

## 2. 总体架构：三轴 + 闭环 + 正交工程轴

**架构图册索引**：D1 总览（本节）· D2 资料处理过程（§3.7）· D3 四要素互动（本节）· D4 方法论组织（§4）· D5 操作组织（§6）· D6 数据分层生命周期（§3.1）。

```
              目标层：三目标 ← 20 机制节点（准入法庭 + 归因坐标系）
                              ↑ 绑定与追溯
        ┌─────────────────────┼─────────────────────┐
        │                     │                     │
     资料轴                方法论轴                操作轴
  L0 原始（不可变）        原理层（教心/脑科学）    环节操作 S1–S9
    ↓ 预处理（纯函数）      通用教学法层            ┌─────────────┐
  L1 策展（账本状态机）     语文教学法层            │ skill＝程序  │
    知识/试题/课文/          ↓ 桥接层（机制节点）    │ 手册＝标准  │
    素材/学生画像            ↓ 双投影                │ 输入→门禁→输出│
    （学生证据另见 L4）      · 手册（人读投影）      └─────────────┘
                            · 注册库（机读投影）          ↓
                                                    教学物料（L3 可再生）
                                                        ↓
    学生证据轴（L4 只追加）：观察/成绩/作品/批改/反思
        ↓ 归因到机制节点
    三条回流边：手册与原则修订 / 学生画像更新 / 知识卡修订 → 下一轮操作

  工程轴（正交垫底）：数据分层/目录/命名/流动/版本/CI——服务以上全部
```

**核心论断**：资料-方法论-操作三角是**供给架构**（怎么生产教学产物）；三目标是**控制问题**（学生状态是否真改变）。三角必须加第四要素——课堂证据轴——才从流水线变成控制系统。本项目既有教训即证明：产物质量在桌面审查中饱和（V4→V6.6 九轮迭代），而三目标零验证，因为证据从未流回。

### D3 四要素互动图（资料 · 方法论 · 操作 · 成绩）

```
        ┌─────────┐   ①供给(知识/素材/学情)   ┌─────────┐
        │  资 料   │ ─────────────────────▶ │  操 作   │
        │原件/整理件│ ◀────────────────────── │ S1–S9   │
        │策展/学生库│   ⑥沉淀(判例/回执入L4)    │skill+手册│
        └────△────┘                          └────┬────┘
             │                                     │
             │⑤慢环:积累(画像/掌握资产)              │②实施+证据挂钩
             │                                     ▼
             │         ┌──────────┐          ┌─────────┐
             │   ④定义 │  方法论   │  ⑧中环:   │  成 绩   │
             │  何为成绩│ 原理→桥接 │  归因→修订 │课堂证据L4│
             └────────▶│ 双投影    │◀─────────│(唯一裁判) │
                       └────△────┘  (仅证伪时) └────┬────┘
                            │③标准(手册+门禁)          │
                            └─────▶ 操作 ◀───────────┘
                                    ⑦快环:调节下一次操作
                                    (回教/分层/调整，不必修方法论)
```

**八条边**：

| # | 边 | 语义 |
|---|---|---|
| ① | 资料→操作 | 供给：知识、素材、**学情**（备课读上次成绩资产） |
| ② | 操作→成绩 | 实施 + 证据挂钩（操作声明本环节采集什么信号） |
| ③ | 方法论→操作 | 标准：手册 + 门禁 |
| ④ | 方法论→成绩 | **定义何为成绩**：节点度量与量规——成绩不是裸分数，是被定义的可观察判据 |
| ⑤ | 成绩→资料 | 慢环：学生证据积累为画像/掌握资产；知识修订提案入 L1 |
| ⑥ | 操作→资料 | 沉淀：判例/审查回执入 L4（操作自己也生产资料性资产） |
| ⑦ | 成绩→操作 | 快环：直接调节下一次操作（回教定向、分层、调整），**不必先修方法论** |
| ⑧ | 成绩→方法论 | 中环：归因到节点→修订手册与注册库（仅规则被课堂证伪时走，防方法论膨胀） |

**三个速度的环**：

| 环 | 路径 | 频率 | 触发条件 |
|---|---|---|---|
| 快环 | 成绩→操作（⑦） | 每课次/每日 | 无条件——操作层适应（回教、分层、下节课调整） |
| 中环 | 成绩→方法论（⑧） | 每单元/偶发 | 仅当规则被课堂证伪——归因修订，投影同步 |
| 慢环 | 成绩→资料（⑤） | 持续 | 自动积累——学生证据沉淀为画像与掌握资产 |

若所有反馈都绕道"方法论修订再指导操作"，系统会官僚化（每改一次课都要先改规则）；三环分工让日常适应走快环、规则只在被证伪时变更。

## 3. 数据架构

### 3.1 五层数据模型（一切处置规则的根据）

| 层 | 内容 | 性质 | 生命周期规则 |
|---|---|---|---|
| **L0 原始层** | 教材、试卷、教辅、课标、新闻、文献、方法论书刊、他人 PPT 等原件 | 不可变 | 只进不改；SHA 登记；永不清理；带权威等级 |
| **L1 策展层** | 知识卡、单元图谱、册表、试题库、课文库、素材库、学生画像 | 账本状态机管理 | 状态流转（drafted→accepted…）；修订走提案；不删除 |
| **L2 设计层** | lesson.json、文本研究、单元规划、作业包、蓝图 | git 版本化 | 候选→冻结→废弃；机器校验入库 |
| **L3 派生层** | 母版/学习单/逐字稿/PPTX/试卷/渲染 + manifest | **可再生**（L2 纯函数产物） | 只留当前版本；旧轮清理（git 历史可回溯）；渲染每版本只提交最终轮 |
| **L4 证据层** | 观察记录、学生作品引用、批改记录、mastery 台账、反思、审查回执 | **只追加** | 永不清理改写；每条绑定课程版本哈希 + 机制节点 |

预处理中间产物属**临时层**：预处理是"原始数据+代码→干净数据"的确定性纯函数，临时文件随时可删、可一键重建。

**资料轴三形态**（整理件与策展件都是资料的一等成员）：

| 形态 | 定义 | 例子 | 与 Tmp 的边界 |
|---|---|---|---|
| 原件 | 外部获取的原始文件 | 教材 PDF、真题卷、期刊 | — |
| 整理件 | **忠实形态转换**（解析/切分/清洗/OCR，确定性、语义无损） | MinerU full.md、切分源包 | 整理件**不是临时文件**：稳定、版本化、被下游日常消费、入册登记；Tmp-work 是管线草稿 |
| 策展件 | **语义加工**（抽取/标注/摘要，含判断） | 知识卡、题库、素材、学生画像 | 血缘须能回溯到整理件/原件核验 |

### D6 数据分层生命周期图

```
Tmp inbox ─ 可删·唯一副本危险区·台账+驻留时限
Tmp work  ─ 可删·确定性可再生
L0 原件    ─ 永存·不可变（§3.7 判据表定子集）
整理件     ─ 永存·版本化·忠实形态（L0 的登记形态）

L3 派生层  ─ 可再生·只留当前版本
L4 证据层  ─ 永存·只追加·绑版本+节点
```

### 3.2 身份与索引原则

知识有**稳定身份**（KP-ID），分类是**派生索引**（按课文、按考点、按任务群、按难度、按题型各一张索引表，指向同一实体）——严禁内容复制（复制品必然漂移）。ID 是四站闭环（课堂→作业→测验→掌握）可机器校验的前提。

### 3.3 权威分级（L0→L1 的入口闸门）

沿用并扩展现有 S1-S4 分级：**S1 规范源**（课标、教材）；**S2 半权威**（教参、官方解析）；**S3 解释性**（文献、期刊、新闻、高质量教辅）；**S4 素材**（他人 PPT、AI 生成、第三方题库）。L1 条目必须带来源权威等级；下游按等级设边界——教材事实/合理推断/他方观点三层不得混写（U6 解释分层的资料面推广）。S4 素材**可直接使用**于教学产物（所有者裁决 2026-08-15），来源仍须登记；其内容作为"知识断言"引用时仍按低权威处理。

### 3.5 血缘铁律

1. L3 每件产物的 manifest 记录：L2 源 SHA + 引用的 L1 卡片 ID + L0 源包 SHA（一键追溯）。
2. L4 每条记录绑定：课程版本哈希 + 来源 + 机制节点编号——无节点绑定的课堂数据不收录。
3. 任何"学生学会了/享受了"的断言只能引用 L4 记录；桌面结论只能引用 manifest + 审查回执。

### 3.6 学生数据治理

两类分治：**可推导的**（成绩→短板，分析产出，带推导链）与**需观察的**（性格、态度，教师录入）。观察类必须带来源、置信度与**有效期**——过期标签自动降权待复核（错误标签会自我实现，兼属伦理问题）。**学生数据如实入库、不脱敏**（所有者裁决 2026-08-15）；有效期默认方案【Q7 待确认】：可推导类随新数据自动刷新（无固定期限），观察类默认一学期到期降权。无证据不落标签（U6 延伸）。

### D2 资料处理过程图

```
外部世界
   ▼
┌──────────── Tmp（永不入 git）────────────┐
│ inbox 落件区：唯一副本·台账·驻留时限      │
│ work  加工区：管线草稿·随时可删·可再生    │
└─────┬───────────────────┬────────────────┘
      │裁决四问：权威?可再生?含判断?版权?   │
      │保留原始             │不留原始(留来源存根)
      ▼                   ▼
┌──────────── 资 料 轴 ────────────────────┐
│ 原件 L0（不可变·SHA·判据表定子集）        │
│   │ ① 无损整理：解析/切分/清洗（确定性）  │
│ 整理件（SRC-PKG/full.md——日常消费形态）   │
│   │ ② 语义加工：抽取/标注（含判断·门禁）  │
│ 策展件 L1（知识卡·题库·素材·学生画像）     │

```

**保留原始的判据**（不以"重要性"判定，用两个客观属性 + 权威等级覆盖）：

| 情形 | 保留原始？ | 理由 |
|---|---|---|
| S1/S2 规范源、半权威（课标/教材/教参/官方解析） | 必留 | 血缘铁律：断言须可回原件核验 |
| 不可再生（独份扫描、易逝网页、易丢失的购置材料） | 必留 | 删即永久失去 |
| 可再生 + 语义转换（文章→观点/考点抽取） | 可删，留来源存根 | 抽取有错误率，存根保底 |
| 可再生 + 纯格式转换（公开 PDF→全文文本） | 可删，留获取路径+SHA | 语义无损，重取即可 |
| S4 素材（他人 PPT、AI 输出、第三方题库） | **可直接使用**（所有者裁决） | 使用自由；来源登记不豁免；作知识断言仍按低权威 |

**配套规则**：①删原始必留**来源存根**（来源描述/获取方式/SHA/日期/可再生路径）——无存根的干净条目不得入册（两本账的资料面底线）；②Tmp-inbox 是唯一副本所在（危险区）：逐件记台账 + 驻留时限（超期未裁决进体检清单），防黑洞；③Tmp 两区**永不入 git**（_staging 260MB 历史教训）；④Tmp-work 由"原始+代码"确定性重建，随时可删。

### 3.8 资料的组织与检索（找得到 + 能理解，双消费者）

设计原则：**人与 AI 的找法不同，但共享同一锚——稳定 ID 与总目录**。

**五层机制**：

1. **物理层**（给人浏览）：目录模仿教师思维路径（册→单元→课文；年份→卷种）；**文件名 = ID 打头 + 人类可读后缀**（`CARD-X3-U01-01_氓.md`）【已裁决】。引用仍只写 ID，解析用前缀匹配（`**/CARD-X3-U01-01*.md`）——实施时迁移存量文件名并同步引用与测试。
2. **解析层**（给机器寻址）：每个 ID 族一条确定性路径规则，汇总为公开的《ID 解析表》（无数据库；AI 读表即可从任意 ID 落到文件）。
3. **目录层**（多分类出现的正确实现）：`work/knowledge/_meta/catalog.jsonl`【裁决：与账本同家，元数据单一权威区】——每实体一行（id/type/title/path/status/authority/tags/updated/summary/last_consumed）。由 catalog **生成**（非手工维护）人读视图：`INDEX.md`、按考点索引、按任务群索引——索引是视图不是复制。
4. **释义层**（冷读可懂）：每件资料头部强制 front matter 五件套：`id/type/title`、`authority`（S1-S4）、`status`（draft 不得被正式产物引用，门禁查）、`source`（血缘/存根）、`relations`、`summary`（一句话：这是什么、给谁在什么情境用）。人读 summary，AI 读 schema 与受控词表。
5. **检索层**【裁决：建最小版】：catalog + 生成脚本（INDEX 与交叉视图）+ ID 解析表即最小版，随实施路线落地；文献/新闻上量后再建倒排/向量索引——索引是派生物（可重建），**检索结果只给 ID+摘录，引用必须落回实体文件核验**（堵"引用索引不核原文"的幻觉路径）。

**防腐三件套**：last_consumed 登记（零消费触发处置，防 81 卡重演）；status 可见（防草稿被当权威）；summary 强制（防空壳）。

**各类资料落位**：

| 类型 | 整理件（可检索形态） | 策展件 | 索引维度 |
|---|---|---|---|
| 课文 | textbook_extract 源包 full.md | CARD + 文本研究 | 册/单元/文体/任务群/主题 |
| 试卷 | exam_extract 切分结构化 | 试卷分析 + 题库条目 | 年份/卷种/题型 |
| 题目 | — | item_bank.jsonl（IB-*） | 题型/考点(KP)/难度/来源 |
| 素材 | — | materials/（MAT-*，待建） | 主题/适用文体/权威等级 |
| 文献/新闻 | 笔记 md（带存根） | 观点条目（挂权威等级） | 主题/方法论节点 |

（AI 找得到的先决条件是一切都有文本形态——原件保真，整理件可检索，这是整理件存在的另一层理由。）

## 4. 方法论架构

### D4 方法论内部组织图

```
原理层（教心/认知/脑科学/发展）──"为什么有效"：不可操作、必须可追溯
   ↓ 细化＝包含＋可操作化
通用教学法层
   ↓
语文教学法层
   ↓
环节手册层 ──────────── 唯一在工作时刻被阅读的层
   ↕ 桥接层（20 机制节点）：原理 ⇄ 可观察判据，双向准入
   ↓ 双投影（同源同步·锚点互通）
   ├─ 手册（人读投影）──教师/agent 共同执行契约
   └─ 注册库（机读投影）──校验器/审查门/准入
通用技术层（PPT/文案/配图/视频）：能力库，被操作调用、受教学门禁裁决
（方法论正文＝资料；两个投影才是活物；工程轴正交、不在本栈）
```

### 4.1 分层与继承

原理层（教育心理学/认知科学/脑科学/发展心理学）→ 通用教学法层 → 语文教学法层 → 环节手册层。继承规则：**细化层包含高层内容并使其可操作；高层不具备直接操作指导意义但必须可追溯**。

### 4.2 桥接层（关键增设）

高层原理与低层操作之间必须有**机制节点**作桥：每条原理落成"可观察判据 + 强制方式"，每条操作规则反向引用原理（准入）。无桥的失败模式项目已付过学费：8100 行理论悬空不被消费；43 条原则失据追认式增长。

### 4.3 双投影

方法论的正文（书籍、理论文档）算**资料**；它的两个**投影**才是活物：**手册**（人读投影：执行时刻看的操作标准）与**注册库**（机读投影：校验器/审查门/准入规则的强制声明）。同源同步：新增方法论落两处，锚点互通、机器核对。课堂判某条规则失效时，顺锚点回原理修订，再重新编译两处投影。

### 4.4 通用技术层

做 PPT、写文案/教案、配图、视频等属**能力层**，被操作层调用，每次调用过教学方法论门禁（判例：通用 PPT 学"标题写结论句"，教学首答态写结论句即泄答，N-04 裁决）。通用技术不与方法论并列建库。

## 5. 操作手册系统（可执行核心）

**定位**：方法论与通用技术的编译目标；教师与 agent 共享的执行契约；系统中唯一在工作时刻被阅读的层。

### 5.1 手册条目标准格式（假设形态）

```
### MM-<环节>-<序号> <规则名>
- 条件：什么情形下适用
- 动作：做什么
- 判据：怎样算做对（含审查门/校验器名）
- 出处：注册库锚点（原则 ID / 机制节点）
- 预期信号：做对了课堂应出现什么证据（节点课堂度量）
```

条目即假设：课堂证据一来，每条规则要么被确认要么被修订（P-37"评估标准先于方案"的手册化推广）。

### 5.2 手册清单与预算

| 环节 | 手册 | 现状 |
|---|---|---|
| S0 资料整理 | 资料整理手册（§3.7 采集协议 + §3.8 组织检索编译为 MM-S0-xx） | 缺（规格已成文待编译） |

**预算与优先级**【所有者裁决 2026-08-15：不设数量上限，以等级管理】：每条手册条目必标**优先级**——P0 核心（执行该环节前必读，保持精简）/ P1 常用（常见情境适用）/ P2 备查（罕见情境与深究）。新增条目仍需节点绑定 + 触发事件（准入不变）；归档协议同 DEVLOG。

### 5.3 需求驱动吸收（"慢慢吸收"的工程化）

资料挖掘的**唯一入口是手册缺口**：执行中撞到手册未覆盖的情形，或课堂证据判某规则失败，才去资料（L0 书刊/文献/他人 PPT）挖掘，增量带出处落成手册条目（必要时同步注册库）。禁止无缺口前向囤积。配套体检：手册与资料条目登记**被哪些操作消费过**，长期零消费者触发处置（补消费方或降级归档）——防"81 卡建成两周无人消费"重演。

## 6.0 工作分类层次（主归属 + 交叉视图）

教师工作分四域：**W1 教学域**（规划 W1.1 / 备课 W1.2 / 实施 W1.3 / 作业与测评 W1.4 / 改进 W1.5）、**W2 学生域**（学情档案 / 学习诊断 / 评定表达 / 个别支持）、**W3 专业域**（教研协作 / 课堂互评 / 研究成长）、**W4 职责域**（班主任 / 家校 / 课外活动 / 行政）。系统边界：W1 全覆盖（S1-S9 即 W1 五块的细化 + S5 质量门）、W2 半建（schema 有数据零）、W2.3 评语与 W3.2 听评课为低成本扩展候选、W3.1/W3.3/W4 明确不纳入。

**组块判据**：每块须有独立的输入/产出物 + 数据形态 + 方法集合（可被一组手册+门禁支撑）；每层 4-5 块封顶。

**交叉规则**（与 §3.2 知识身份与索引原则同构——全系统只有一个分类哲学）：

1. **身份唯一**：每项工作一个稳定 ID（TW-\*），描述只写一处；
2. **主归属唯一**：按主要产物落点定主归属——手册与门禁安家之处、预算计数之处；
3. **交叉＝视图索引**：视图是派生索引（链接），不是内容复制。三条正交视图轴：周期轴（学期级/课次级/即时级/跨级）、对象轴（知识/学生/同行/家长）、产物轴（物料/数据/判断/关系）；
4. **预算与审计按主归属计一次**，视图重复出现不重复计数。

典型交叉项：答疑辅导（主 W2.4；即时与课后视图）、阅卷统计（主 W1.4；产物入 W2.2 资产）、差异化应对（主 W1.3；依据 W2.1）、讲评课（主 W1.4；形态挂课堂实施视图）、听评课（主 W3.2；发现喂 W1.5）。

### 操作自身的规约与审核（元标准，位于工程轴）

操作与手册是**两种标准、两个对象、两个家**：

| | 产物标准 | 操作规约 |
|---|---|---|
| 管什么 | 产物对不对（这页 PPT、这份试卷合格吗） | 操作本身对不对（流程正确、完备、可执行吗） |
| 家 | 手册层（方法论轴） | 工程轴（元层） |
| 谁关心 | 教师 + agent | 仅系统维护方（教师永不审此） |

**操作规约五件套**（每个 skill/流程必备）：①输入/输出实体（数据流契约）；②引用完整性（步骤引用的 MM 条目/原则 ID 真实存在，可机器查）；③放行条件（操作自身的判据）；④证据挂钩（声明本环节采集什么信号）；⑤跑得通（回归测试 + selfcheck 绿）。

**三个审核时机**：入库（五件套齐全 + 服务某机制节点——准入法庭对操作同样生效）；变更（全量测试绿 + 引用未断）；执行失败（归因第三行：数据流断裂/工具坏 → 工程轴修订）。

**边界纪律**：规则只在手册（skill 步骤引用条目 ID，不得硬编码阈值——防两处漂移）；顺序只在操作（手册条目不得含流程语——保跨情境复用）。理由：规则与流程是多对多引用（同一规则被多环节引用，同一步骤引用多条规则），合并即复制，复制即漂移——本项目 43 条原则膨胀与禁词表 10+ 处拷贝两个病史均为"规则与流程纠缠"所致。

**失败归因表**：

| 现象 | 责任侧 | 修订落点 |
|---|---|---|
| 产物违反某 MM 条目，但操作流程没有引用它的步骤 | 操作漏引用 | 改 skill（补步骤引用） |
| 产物错了，但所有适用 MM 条目都通过 | 规则缺口 | 改手册（需求驱动吸收，走中环） |
| 操作跑不通（读不到输入实体、门禁崩） | 工程问题 | 改工程轴（数据流/工具） |

### skill 总表与准入规则

**操作与 skill 的关系**：操作 = 数据流契约单位（读什么实体→过什么门禁→写什么实体）；skill = 操作的执行包装，一个 skill 可编排一到多个操作。近期共 **19-20 个 skill**：

| 组 | skill | 状态 | 编排的操作 |
|---|---|---|---|
| 资料轴 | `yuwen-intake` | 待建 | 外部→Tmp-inbox 台账→裁决四问→L0/存根（§3.7） |
| 资料轴 | `yuwen-organize` | 待建 | 原件→整理件（解析/切分/清洗；类型配方配置化：教材/试卷/文献） |
| 资料轴 | `yuwen-curate` | 待建 | 整理件→策展件（语义加工门禁：权威等级/血缘/账本） |
| 资料轴 | `yuwen-catalog` | 待建 | catalog 增量→视图生成→消费登记→零消费体检（§3.8） |

| 工程轴 | `yuwen-flow` | 待建 | 按环节跑门禁链 |

远期（配图/视频/文案等通用技术 skill）按需求驱动吸收建，不预设。

**预处理 skill 内嵌规格的三条硬机制**：①步骤即规格引用（引 MM-S0-xx 条目 ID，不重述规则）；②门禁兜底（入册门禁在末步强制跑，不过不落 L1——规格靠机器拦不靠自觉）；③catalog 回写（每个资料轴 skill 末步登记增量与 last_consumed）。

**skill 准入规则**（防 skill 重演原则库膨胀）：新建 skill 必须声明——①服务的机制节点；②对应操作（读/门禁/写）；③手册归属（S0-S9 册）；④操作五件套齐备。且**默认答案是扩旧 skill 而非建新**，例外才建。

## 7. 闭环与三条回流边

**三环速度**（对应 D3 边⑦⑧⑤）：快环＝回流边①（成绩→操作，每课次、无条件）；中环＝回流边②（成绩→方法论，仅规则被课堂证伪时）；慢环＝回流边③与学生证据持续积累（成绩→资料）。

课堂证据按机制节点归因后回流：①**S8→S1/S7**：掌握低于阈值自动生成回教提案（绑卡片与页面），下一作业定向补检索；②**S9→注册库/手册**：原则修订提案（触发证据+节点+强制方式）过收敛门禁入 STANDARD 下一版；③**S9→L1**：知识卡修订提案（课堂证明卡片有误）走 L1 状态机。回流边工程化前，闭环靠人工——这是当前架构与目标的距离所在。

## 8. 工程轴（正交，服务全部轴）

已定方向：依赖与环境基建（package.json/requirements.txt、去硬编码路径）；五层数据规则落地（L3 历史轮清理、L4 目录骨架）；lesson.json canonical 化（内联 JS 链、lib/theme 引擎化）；门禁闭环（run_flow 按环节跑门禁链、selfcheck 扩容、CI）；知识/高考线引擎化（kp_batch 配置化、exam 统一入口）；证据层 schema 与回流边工程化；文档与 DEVLOG 收口。原则：工程让三轴流动**就绪**，不替代其真实运行。

### 8.1 建设质量协议（对建设过程自身的质量保证）

核心原则：**不靠"更小心"，靠"系统不允许不小心"**——对建设者自身的信任度与对课件的信任度设同一上限：都是未经证伪的候选。

**四层防线**（均已运行且拦到过真实缺陷）：
1. 机器门禁：测试先行+全量回归；run_selfcheck；反样板检查；词表漂移核对；CI。判例：注册库校验器首跑抓出 34 处错误；反样板检查抓出 462 处模板默认串（均为建设过程自身产物）。
2. 结构防错：准入法庭（无节点不收录）；双投影+锚点核对；单一真相源；预算机制（防膨胀）；失败归因表（定位改哪）。
3. 过程纪律：DEVLOG 归档可审计；每 workstream 一提交、全绿为门禁；契约先行（schema 先于数据、手册条目先于校验器）。
4. 诚实机制：两本账（永不声称课堂效果）；现状映射如实分三档；"一轮零发现先怀疑检查力度"（P-29）同样适用于自身 QA。

**三个已知残余风险**：①同眼盲区（我写我查；判例：LRN 记录用户四次纠正同一根因而机器审查未先发现）；②文档-实现漂移（判例：C604 info_state 措辞与实现不符，靠视觉评估交叉核对才抓到）；③建设自嗨（判例：81 卡建成两周零消费）。

**三个补强机制**（对应三风险，待实施）：
1. **新鲜眼审查制度化**：重要工程产物（新校验器/新 skill/大重构）合入前，由未参与编写的子代理冷读审查，并**先写攻击性反例测试**（"先写一个能打败自己实现的用例"再实现）。
2. **规格即判据**：写进本方案的每条条款必须自带"如何被机器或审查检验"——无判据的条款不收（准入法庭对工程条款同样生效）；v1.0 定稿前逐条补判据。
3. **否决回流**：所有者的每次否决/纠正记入 `.learnings`（Recurrence ≥2 自动升格为纪律）——在系统建成前，所有者审计点即收敛规则中"外部锚点"的桌面替身。
