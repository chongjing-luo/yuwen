# L0 统一治理专项方案（v0.9 · 待裁决）

### 1.2 双份机制（524MB 的来源）

MinerU 结果包内 `<uuid>_origin.pdf` 是源 PDF 的**重序列化副本**：内容相同、字节不同。
实测 2017 解析卷：源与 origin 均 15MB，sha256 分别为 `54bf…` / `a2a3…` ——
**哈希去重不可用，必须内容级校验**。旧真题目录内 origin.pdf 副本合计 **294M**（工作树），
与之配对的源 PDF 约 230-294M 同目录并存。

### 1.3 引用面（账本手术的影响范围）

- `Data/reference/gaokao/registry/artifacts.jsonl`：登记账本引用该目录。
- `work/knowledge/_meta/exam_*_20260809.json` 等 7 份：历史审计记录（性质为只追加证据，**不改写**）。
- `work/knowledge/_meta/catalog.jsonl`：**零引用**（新目录体系未吸入旧路径，手术无 catalog 面）。

## 二、选项

### 方案 A（推荐）：工作树去重 + 增量纪律 + 历史缓议

1. **配对等价校验**：17 对（源 PDF, origin.pdf）逐对做内容等价验证（pypdf：页数一致 + 逐页文本哈希一致）；不等价者单列裁决，不默认删除。
2. **删工作树 origin.pdf**（仅等价对）：MinerU 包保留 layout/解析产物；L0 原件唯一化为源 PDF。
3. **账本只追加**：artifacts.jsonl 补记「origin 并合」事件（新路径=源 PDF、新 SHA），不覆盖旧记录（L4/账本只追加纪律的推广）。
4. **_staging 退出索引**：`git rm --cached -r` 已跟踪的 108 对象，磁盘保留；恢复「不入 git」纪律的执行面。
5. **历史不动**：pack 1.06GiB 留待自然断点（对外共享/迁移仓库前）再议 filter-repo——commit 哈希重写会破坏 DEVLOG、规格、审计回执中的全部哈希锚点，收益（约 -400~500M）不抵协调成本。
6. **垃圾清理**：与试卷会话协调空窗后 `git gc --prune=now` 清 tmp_obj。

- 收益：工作树 -294M；账本与物理一致；纪律闭环。
- 代价：一轮账本手术 + 全量回归。
- 风险：内容等价校验的假阴性（扫描件无文本层时逐页文本哈希失效 → 降级为页数+尺寸+渲染抽验，或该对保留）。

### 方案 B（激进）：含历史重写

在 A 之上追加 `git filter-repo`：剥离 `_staging` 与 origin.pdf 的历史 blob，pack 预计 1.06GiB→约 0.6GiB。
代价：**全部 commit 哈希重写**——DEVLOG 引用的 677e9b5/dae2e90 等、规格文档、审查回执内的哈希锚点需全面迁移；两会话必须冻结协调。仅在未来确需瘦身（克隆/共享）时值得。

### 方案 C（最小）：仅增量纪律

不动旧目录，只对增量立规（下述第三节）+ gc 清垃圾。旧双份留待下次专项。
适合：若裁决「294M 工作树成本可接受、先让试卷线跑完」。

## 三、增量纪律（无论选哪项都建议立即生效，对 9.9G 新语料适用）

1. **L0 原件唯一**：每个实体只保留一份原件（源 PDF 或采集原件），ledger 登记 SHA；
2. **MinerU 包入 git 前剥离 origin.pdf**（或整个解析结果包不入 git、只入策展产物——与 `_staging` 同规）；
3. **大对象入册门槛**：>10M 单件入 git 前须过「可再生？账本必需？」两问，否则外置 + 路径登记。

> 协调点：试卷线（分工会话）正在处理 `Data/高考语料`，本纪律建议在其本批收口后
> 由该会话执行回扫，避免两个会话同时动同一目录。

## 四、验收标准（执行轮）

- 工作树体积下降 ≥290M（方案 A）；
- `git ls-files work/knowledge/_staging` 为空；
- artifacts.jsonl 出现并合事件且 catalog `--check` 通过；
- 全量测试绿（试卷线 2 个预存红测除外，见 DEVLOG 6）；
- 历史审计 JSON（20260809 系列）字节不变。
