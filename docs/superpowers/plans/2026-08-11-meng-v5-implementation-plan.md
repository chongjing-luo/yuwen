# 《氓》V5全文逐句教学母版实施计划

日期：2026-08-11  
状态：用户已确认V5规格，进入实施  
依据：`docs/superpowers/specs/2026-08-11-meng-v5-text-spine-lesson-design.md`

## 1. 实施目标

从同一份V5课程数据生成并验证：

- 完整教案Markdown/DOCX；
- 学生学习单Markdown/DOCX；
- 逐页无生试讲稿Markdown/DOCX；
- 约95—120页完整PPTX母版及五个同源模块PPTX；
- 学生接收桌面审计、母版—模块页码映射、机器验证报告与交付清单。

V4文件只作历史参照，不覆盖、不删除。V5使用独立文件名和生成链。

## 2. 依赖关系

```text
V5规格
  ↓
V5验证合同（先失败）
  ↓
共享课程数据（30组诗句、12句群、五模块、逐页脚本）
  ├──→ Markdown教案/学习单/试讲稿/审计
  ├──→ PPTX母版与五模块
  └──→ DOCX三件套
          ↓
内容验证 → Office验证 → 全量渲染 → 独立双审 → 修复复验
```

## 3. 任务清单

### Task 1：建立V5验证合同（S）

**说明：** 新建V5验证器与单元测试，先定义30组覆盖、三问同措辞双现、责任/困境分离、12句群、全文首读/复读、五模块、PPT备注、母版/子课件和前台禁词。

**验收：**

- [ ] 新测试在V5文件尚不存在时明确失败；
- [ ] 测试覆盖遗漏诗句、责任混线、答案提前显示、缺备注和缺模块课件；
- [ ] 不修改V4验证器和V4测试预期。

**验证：** `python -m unittest tests.test_validate_meng_v5_lesson_package -v`

**依赖：** 无。

**涉及文件：** `scripts/validate_meng_v5_lesson_package.py`、`tests/test_validate_meng_v5_lesson_package.py`。

### Task 2：建立共享课程数据与Markdown生成（M）

**说明：** 新建V5课程数据和内容生成器，首先贯通“模块一+第一章”，再扩展到六章和三问总结。每页必须含学生可见状态、分钟、模块、页型和连续剧本。

**验收：**

- [ ] 30组诗句与12句群完整且顺序固定；
- [ ] 五模块总时长230分钟；
- [ ] 第一章双重观看使用四层解释边界；
- [ ] 生成教案、学习单、试讲稿和学生接收审计Markdown；
- [ ] 逐页脚本包含承接、教师原话、学生动作/等待、必要分支、证据和切页句。

**验证：** V5单元测试通过Markdown合同；人工抽查每章首尾、Q3和第一章回看。

**依赖：** Task 1。

**涉及文件：** `scripts/meng_v5_lesson.js`、`scripts/build_meng_v5_markdown.js`及V5 Markdown交付物。

### Checkpoint A：内容骨架

- [ ] V5测试由红转绿；
- [ ] 六章各5组、共30组覆盖；
- [ ] 责任线和困境线无相互致因箭头；
- [ ] 提交一个可回退的内容增量。

### Task 3：生成PPTX母版与五模块（M）

**说明：** 新建PptxGenJS生成器。采用原文/释义/关键观察、问题/作答/回收分屏；从同一页面数组筛选五个模块，写入同源讲者备注和页码映射。

**验收：**

- [ ] 母版约95—120页，五个模块页数与映射一致；
- [ ] 原文44—60pt、译文30—36pt、正文≥28pt、注释≥24pt、页脚≥18pt；
- [ ] 每章逐句页n/5连续并显示累计动作链；
- [ ] 三问使用总览+逐问独页，并在回收阶段同页型重现；
- [ ] 第一章首次前台不出现“警告信号、伪装、恋爱脑、信息遮蔽”；
- [ ] 每页含连续讲者备注，母版与模块备注同源。

**验证：** V5 PPTX合同、Office结构验证、文本提取；渲染后至少一次全量视觉修复循环。

**依赖：** Task 2。

**涉及文件：** `scripts/build_meng_v5_pptx.js`及6个V5 PPTX交付物。

### Task 4：生成DOCX三件套（S）

**说明：** 复用现有docx-js Markdown解析模式，为V5教案、学习单和试讲稿生成A4文档，设置标题层级、页眉页脚、双宽表格和页码。

**验收：**

- [ ] 三份DOCX均成功生成并通过Office结构验证；
- [ ] 30组覆盖表、模块表和三问表无异常压缩；
- [ ] 页面、标题层级、表格、页码正常。

**验证：** `scripts/office/validate.py`，LibreOffice转PDF，全页渲染抽查。

**依赖：** Task 2。

**涉及文件：** `scripts/build_meng_v5_docx.js`及3个V5 DOCX交付物。

### Checkpoint B：可用交付物

- [ ] Markdown、DOCX、母版PPTX和五模块PPTX全部可打开；
- [ ] 自动合同和Office验证通过；
- [ ] 提交PPT与DOCX生成增量。

### Task 5：质量报告、方法论与交付封存（S）

**说明：** 更新《氓》V5专用设计标准、实施计划、质量记录、方法论变更摘要、机器报告、页码映射和SHA-256交付清单。旧V4明确标为历史版本。

**验收：**

- [ ] 所有当前文件名、页数、时长、模块和术语一致；
- [ ] 只报告设计和桌面验证，不声称真实课堂效果；
- [ ] 交付清单包含完整母版、五模块、三DOCX和全部Markdown。

**验证：** 全量V5验证器零错误，清单哈希复核一致。

**依赖：** Task 3、Task 4。

### Task 6：独立双审与闭环（S）

**说明：** 由学生接收审查agent和PPT视觉审查agent分别检查成品；只关闭可由桌面证据判断的问题。

**验收：**

- [ ] 视觉审查覆盖全部母版页面并抽查模块一致性；
- [ ] 学生审查覆盖首次接收、逐句连续性、三问回收和伦理边界；
- [ ] P0/P1全部关闭；
- [ ] 至少一轮发现问题—修复—定点复验完成。

**验证：** 审查记录、修复记录、最终机器报告与渲染结果相互一致。

**依赖：** Task 5。

## 4. 风险与控制

| 风险 | 控制 |
|---|---|
| 逐句教学变成100页答案堆叠 | 一页一个认知动作；30组后台覆盖、12句群前台推进；章首章末完整朗读 |
| 脚本数量大而干瘪重复 | 先写模块一完整剧本作样板；每页脚本必须对应可见状态；讲解页不虚构分支 |
| “恋爱脑/伪装”越界 | 四层解释合同；首次前台禁词；回看必须显示“文本不能证明” |
| 责任线与困境线混写 | 数据模型分开字段；验证器禁止从投入指向粗暴的因果表述 |
| 母版过长难定位 | 五个同源模块子课件；教师索引；安全停点与续接页 |
| PPT/DOCX跨平台错位 | 固定字体、字号和页面尺寸；Office验证；LibreOffice全量渲染 |
| 脏工作区误提交 | 每次只暂存V5明确文件；提交前检查staged diff和敏感词 |

## 5. 完成判定

只有Task 1—6全部完成、V5自动合同零错误、Office结构有效、全量渲染完成、双审P0/P1关闭时，才报告“V5桌面设计交付完成”。真实课堂学习与体验仍须另行试教验证。
