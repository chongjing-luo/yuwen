# 语文备课三阶段 skill 架构设计

## 一、问题与设计结论

当前单篇备课链是“文本研究 S2 → 教学设计 S3 → 物料 S4”，但人读教案没有独立的主 skill、产物契约和门禁。结果是：

1. “写教案”被塞在 `yuwen-design-lesson` 的第一步，教案容易退化为页面设计前的说明；
2. 文本研究、教案和教学设计都在决定知识范围、贯穿问题与教学顺序，最终裁决权重叠；
3. 教案审核没有与具体文件哈希绑定，下游无法证明自己消费的是已批准版本；
4. `yuwen-flow` 用同一个 lesson schema 校验 S2 与 S3，不能识别证据、教案和教学设计是三种不同对象；
5. 单元规划、教案、教学设计和物料之间缺少可失效的哈希链，上游改变后下游可能继续冒充有效。

本次采用“三个正式阶段主 skill＋专业支持 skill＋工程门禁 skill”的架构：

```text
S1 单元规划（上游）
  ↓
S2 第一阶段：证据准备 G0 → 教案 G1
  ↓
S3 第二阶段：教学设计 G2
  ↓
S4 第三阶段：PPT与物料 G3
  ↓
S5 独立终审候选 G4 → 宿主项目外放行
```

三个阶段是正式教学成果的生成顺序；G0 是第一阶段内部的证据准备，不另立第四个正式阶段；G4 是质量门，不是内容制作阶段，项目内最多形成`awaiting_host_release`候选，不能自称宿主已放行。

## 二、“整体教学逻辑”放在哪里

### 1. 裁决

**整体教学逻辑保留在教案阶段，教学设计另写课堂运行逻辑。** 不把整体教学逻辑整体后移到教学设计。

若教案只有目标和知识清单，没有完整课程怎样展开的论证，它就不能证明这些内容能组成一堂有因果、有体验、有收束的课；教学设计会被迫同时重做“教什么”和“怎样教”，第一道审核因此失去意义。

### 2. 教案中的整体教学逻辑

整体教学逻辑不是“课文内容讲授顺序”，而是**整堂课程的宏观叙事与因果合同**，必须覆盖实际需要的全部教学组成：

- 学生从何种旧知、经验、声音、问题或情境进入；
- 导入为什么这样设计，它为后文提供什么真实前提；
- 作者、出处、体裁、写作背景、时代背景分别在何处、为何进入，而非默认堆在课首；
- 课文怎样初读、细读、逐句或专题展开，知识怎样在原文位置生长；
- 贯穿问题怎样提出、悬置、积证、讨论、修订和回收；
- 教师微讲、示范、朗读、背景补充与学生生成之间怎样分工；
- 何处重新整体化、检索知识、总结方法、完成背诵或迁移；
- 学段旧知、高考材料、现实问题与热点材料若确有功能，怎样进入并回到本课；没有可靠关联时怎样如实不呈现；
- 认知、情感与文学体验如何递进，最后把学生带到哪里。

教案以“一段连续完整的整体逻辑＋阶段骨架＋目标/知识落实总表”共同表达。连续段说明为什么这样走；阶段骨架说明每段承担什么；落实总表证明每项目标和每条必教/检索旧知都已入线。此层可决定整体—局部—整体、逐句讲授或专题研习、主要阶段顺序、知识的初步处理方式与完整母版课时，但不写逐分钟口令、页面标题、版式和逐屏台词。

整体教学逻辑必须至少绑定 K1、K2、U8 与 J4；涉及全课负荷、节奏或跨课关系时，同时绑定 K4、K5、U5、J5。它要通过四项反证：删除阶段是否断链、调换阶段是否缺前提或泄答、学生能否复述自己的理解变化、是否有目标或必教 KID 游离在主线外。

### 3. 教学设计中的课堂运行逻辑

课堂运行逻辑把教案的宏观阶段变成可以实际发生的事件链，逐事件说明：

- 此刻学生看到、听到、读到什么；
- 学生思考、朗读、书写、讨论、比较、修订什么；
- 学生可能有什么认知变化、情绪变化与正常反例；
- 教师何时等待、追问、示范、补充背景、精讲、校准和收束；
- 形成什么可见产物，后续事件怎样真实调用；
- 事件如何过渡，使用哪个物理画面，持续多少时间；
- 哪个失败信号触发哪条分支。

教学设计可以在不改变上游合同的前提下优化活动手法、事件粒度、页面数量、分组方式、过渡语言与时间分配。若发现阶段顺序、目标、必教 KID、defer、贯穿问题或完整母版结构不可执行，必须提出上游修改，重做教案并重新通过 G1，不能在第二阶段暗改。

## 三、skill 拓扑与裁决权

| 类型 | skill | 唯一职责 | 无权决定 |
|---|---|---|---|
| 上游主 skill | `yuwen-plan-unit` | 单元定位、课时分配、KP复现排程、跨课回投 | 单篇课的最终目标和课堂顺序 |
| 第一阶段主 skill（新） | `yuwen-author-lesson-plan` | 统筹 G0 证据，裁决目标、知识全账、贯穿问题、整体教学逻辑和阶段骨架，生成并锁定教案 | 逐事件程序、页面、视觉与逐屏台词 |
| 第一阶段支持 skill（保留） | `yuwen-research-text` | 裸读细读、教材回源、事实/解释边界、候选 KID、困难和候选贯穿问题 | 最终目标、必教/defer、贯穿问题、阶段顺序 |
| 第二阶段主 skill | `yuwen-design-lesson` | 只消费已批准教案，把宏观逻辑落实为课堂事件链、学生经历、页面功能合同和课程数据 | 暗改教案合同、制作视觉成品 |
| 第三阶段主 skill | `yuwen-build-materials` | 从已批准课程数据同源生成 PPT、逐屏真实剧本、学习单、板书和其他物料 | 新增知识、改目标、改活动机制、改信息顺序 |
| 工程门禁 skill | `yuwen-flow` | 运行 G0—G4 对象专属验证器，报告通过、失败和失效链 | 生成或改写教学内容 |
| 最终审计 skill | `yuwen-audit-lesson` | 机器检查、反样板、视觉与学生接收双审、冻结待宿主放行候选 | 作为第四个内容制作阶段或在项目文件内自称已放行 |
| 全局治理 skill | `yuwen-selfcheck` | 注册库、机制覆盖、测试、两本账与项目健康检查 | 代替阶段门禁或课堂证据 |

`yuwen-research-text` 保留为可单独调用的专业支持 skill，因为教师可能只需要研究文本，也因为裸读、PDF回源和解释边界值得独立复用；但其输出全部标为“候选”，最终裁决只能发生在 `yuwen-author-lesson-plan`。

## 四、三阶段输入、产物与禁止越界

### 1. 第一阶段：`yuwen-author-lesson-plan`

**输入**：S1 单元规划（存在时必须消费）、教材 PDF 与解析件、课标、教材栏目、知识卡/单元图谱/册级汇总、教师用书与研究资料、已学及后续课文、高考真题、按需的时代材料、真实学情或“暂无”声明。

教材与课标以 PDF/规范原件为证据根，MinerU/Markdown 是定位和检索层，不能反过来成为唯一规范源。若 PDF 与解析件冲突，先回到 PDF 裁决并登记差异。

**正式产物**：`work/teaching/<册>/<课>/教案.md`。

**支持产物**：文本研究与证据档案、证据清单、G1 所有者回执和教案锁。

**教案最低合同**遵循 `work/备课/语文备课操作规程.md`：五个坐标、文化背景、学情与独特价值、目标及达标证据、14类知识全账、贯穿问题/重点/难点、完整整体教学逻辑、阶段骨架、落实总表、风险/来源/两本账与审核。高考是每课必查、按需呈现；没有可靠或有用关联时记录 E0，不强造 PPT 固定页。

**禁止**：逐页版式、颜色、插图、逐屏台词、分组口令；用活动想法掩盖知识缺口；把文本研究候选直接当最终裁决。

### 2. 第二阶段：`yuwen-design-lesson`

**输入**：当前教案、有效 `lesson_plan_lock.json`、G1 回执、证据档案、原则注册库、手法库与视觉功能规范。

**产物**：`教学设计.md`、`lesson.json`、`design_lock.json`。教学设计必须同时包含课堂事件链、学生体验/认知/情绪变化、教师作用、参与与正常反例、形成性证据、过渡、时间盒、页面/物理状态规划；`lesson.json` 是这份人读教学设计的机器化，不是反过来替代它。

**锁定边界**：目标 ID、必教/检索旧知 KID、defer、贯穿问题、阶段顺序、完整母版总时长与宏观收束方式默认不可改。页面数量、事件粒度、活动手法、分组方式和局部时间可在阶段预算内优化。

**禁止**：先画页面后找功能；用模板字段充数；在教学设计里悄悄新增知识或重写课程主线。

### 3. 第三阶段：`yuwen-build-materials`

**输入**：当前 `lesson.json`、有效 `design_lock.json` 和 G2 通过记录。

**产物**：PPTX、逐物理画面真实课堂剧本、学习单、板书/卡片/音频等必要物料、渲染结果、manifest 和 `materials_lock.json`。

每一页 PPT 的功能来自教学设计；学生可见区只呈现此刻必须面对的文本、材料、问题、任务要求和活动后共同发现，不呈现学生画像、教学目标、设计理由、代理思路、失败信号或机器语言。每个物理画面下均有可真实执行的剧本，不以干瘪提纲代替课堂发生。

**禁止**：手工分叉修改单一成品；制作阶段改变目标、知识范围、活动机制或信息顺序；用插图和装饰替代页面功能。

## 五、产物锁与失效传播

所有哈希均为完整文件 SHA-256；审核必须绑定审核时的对象哈希。

```text
evidence_manifest.json
  ↓
教案.md + G1_owner_approval.json
  ↓ lesson_plan_lock.json（绑定 evidence + 教案 + G1回执）
教学设计.md + lesson.json
  ↓ design_lock.json（绑定 lesson_plan_sha256 + 两项设计产物）
PPT/剧本/学习单/板书 + manifest
  ↓ materials_lock.json（绑定 design_hash + manifest_hash）
G4审计候选冻结（绑定 materials_lock_hash + 标准版本/注册库与执行配置hash；status=awaiting_host_release）
```

建议统一放在 `work/teaching/<册>/<课>/_meta/`：

- `evidence_manifest.json`
- `G1_owner_approval.json`
- `lesson_plan_lock.json`
- `design_lock.json`
- `materials_lock.json`

G1 回执至少含 `lesson_id`、`reviewer_id`、`decision`、`reviewed_at`、`lesson_plan_path`、`lesson_plan_sha256`、`standard_version` 和待裁决项结论。`lesson_plan_lock` 只有在回执为通过且审核哈希等于当前教案哈希时才能生成。

下游锁必须包含上游锁的对象哈希。任一上游对象改变后：

1. 当前环节验证器立即失败并报告第一个断点；
2. 该点之后所有产物标为 stale，不得继续放行；
3. 回到被修改的阶段重新审核；
4. 下游重新生成、复验，不允许只改哈希。

## 六、五道门与专属验证器

| 门 | 验证对象 | 机器检查 | 人工/所有者检查 |
|---|---|---|---|
| G0 证据门 | `evidence_manifest.json` 与证据档案 | 新建 `validate_lesson_evidence.py`：路径、SHA、规范原件优先、引用可解析、关键来源齐备 | 关键解释边界、来源可信度与缺口是否诚实（K1/U6/J7） |
| G1 教案门 | `教案.md`、G1回执、`lesson_plan_lock.json` | 新建 `validate_lesson_plan.py`：目标/KID/阶段稳定ID，目标与KID全覆盖，defer有理由，落实表无孤项，回执与哈希一致 | 所有者审查独特价值、知识完整性、整体教学逻辑与课程合理性（K1/K2/K5/U8/J4） |
| G2 设计门 | `教学设计.md`、`lesson.json`、`design_lock.json` | 扩展 `validate_lesson_schema.py`：绑定教案哈希、事件/页面合同、时间守恒、上游锁定字段不漂移；反样板检查 | 学生经历、教师作用、活动后用、节奏、文学质地与心理安全（U1—U8/J1—J7） |
| G3 物料门 | 全部成品、manifest、`materials_lock.json` | 构建测试、跨物料一致性、前台禁词、备注/逐屏剧本存在、设计哈希绑定 | 朗读测试、视觉 QA、真实剧本可执行性（K2/U1/J3/J4） |
| G4 终审候选门 | 冻结物料包 | 原则检查、反样板、manifest/锁链、渲染检查、冻结配置与宿主外部事件核对 | 视觉功能审查＋新鲜学生接收审查；P0/P1/P2清零或按收敛规则处理；本地只产`awaiting_host_release`，宿主另行放行（J7） |

机器检查只验证可确定的结构、血缘和覆盖关系，不用标题正则冒充文学质量判断。知识是否准确、整体逻辑是否成立、文字是否有语文质地，必须保留为有明确证据要求的审核门。

## 八、迁移与兼容策略

1. 不删除 `yuwen-research-text`，只收窄裁决权，避免旧调用突然失效；
2. 现有未进入教学设计的《沁园春·长沙》教案作为首个 G0/G1 迁移样本，补证据 manifest、所有者回执和锁；未获所有者批准前仍为 G1 候选；
3. 《氓》历史产物不被新标准追溯否决；其下一次主动重建才迁入新链，符合不追溯否决原则；
4. 旧 lesson 数据在迁移前标 legacy，不冒充通过新 G2；
5. 正式目录只保留当前入口和当前版本，旧技能职责与旧手册文本由 git 历史保存，不并列维护第二套流程。

## 九、验收标准

架构实施完成必须同时满足：

1. 新 agent 从项目入口能唯一识别“教案 → 教学设计 → PPT与物料”三阶段主链；
2. “整体教学逻辑”明确覆盖导入、背景、文本、知识形成、讨论、总结、迁移与按需高考/现实材料，不再被理解为课文讲解顺序；
3. `yuwen-research-text` 不能再裁决最终目标、必教/defer、贯穿问题和阶段顺序；
4. 没有有效 G1 回执和教案哈希，`yuwen-design-lesson` 与 G2 验证必须拒绝继续；
5. 教案改变会使设计和物料失效，设计改变会使物料失效；
6. 三个主 skill 的输入、产物、禁止越界和失败回流无重叠、无断点；
7. 高考“每课必查、按需呈现”，不存在无可靠关联仍强制生成 PPT 页的规则；
8. 所有新规则至少绑定一个 K/U/J 节点并落到 machine check、design trace 或 review gate；
9. 独立新鲜上下文 agent 用一个真实课文请求试跑后，不会跳过教案直接写 lesson.json 或 PPT；
